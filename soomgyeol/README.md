# 숨결 (Soomgyeol)

지금 마음에 맞는 호흡을 빛과 소리로 안내하는 호흡 코치.
「유료 앱과 웹사이트 공통 개발 요청서 1.0」에 맞춰 만든 MVP입니다. 하나의 Node 서버가 아래 네 가지를 함께 제공합니다.

| 경로 | 내용 |
|---|---|
| `/` `/features` `/pricing` `/support` | 소개 웹사이트 (서버에서 HTML 생성, 검색엔진용 제목·설명·공유 이미지·사이트맵) |
| `/terms` `/privacy` `/refund` | 약관·정책 초안 (`[운영자 확인 필요]` 표시) |
| `/app` | 실제 사용하는 웹앱 (PWA, 홈 화면에 추가 가능) |
| `/admin` | 관리자 (role=admin 만, 서버에서 검증) |

## 실행

Node 22.13 이상만 있으면 됩니다. 외부 패키지가 없어 `npm install` 이 필요 없습니다(DB는 Node 내장 SQLite).

```bash
cp .env.example .env            # 값 확인 (아래 "출시 전 할 일" 참고)
ADMIN_EMAIL=me@example.com npm start
# http://localhost:3000        소개 사이트
# http://localhost:3000/app    웹앱 (ADMIN_EMAIL 로 가입하면 관리자)
# http://localhost:3000/admin  관리자
npm test                        # 서버 테스트 12개
npm run seed-demo               # 데모 회원 12명 (@demo.soomgyeol, 실제 회원과 구분)
npm run make-admin -- me@example.com
```

`.env` 파일은 자동으로 읽지 않습니다. 배포 환경의 환경 변수로 넣거나 `node --env-file=.env server/index.js` 로 실행하세요.

## 2장 앱별 입력 사항 (가정 포함)

| 항목 | 이번 MVP의 값 | 상태 |
|---|---|---|
| 앱 이름 | 숨결 | 확정 필요 |
| 한 줄 소개 | 지금 마음에 맞는 호흡을 빛과 소리로 안내하는 호흡 코치 | 가정 |
| 주요 고객 | 긴장·감정 기복이 잦은 직장인·1인 사업자, 잠들기 어려운 사람 | 가정 |
| 해결할 문제 | 언제 어떤 호흡을 몇 초씩 해야 할지 혼자 정하기 어려움 | 가정 |
| 고객이 얻는 결과 | 2~5분 안에 진정, 전후 기분 기록으로 나에게 맞는 호흡 파악 | 가정 |
| 핵심 기능 | ① 마음 상태 질문 → 호흡 추천 ② 입자 그림·음성·음악 안내 ③ 기분·메모 보관함 | 구현 |
| 출시 채널 | 반응형 웹 + PWA. iOS/Android/토스 미니앱은 이후 | 가정 |
| 무료 제공 범위 | 3가지 호흡, 하루 3회, 1회 최대 3분, 최근 7일 기록 | 가정 |
| 유료 구매 이유 | 화·불면·복잡한 생각용 호흡(용암·4-7-8·교호), 긴 세션, 전체 기록 | 가정 |
| 과금 방식 | 월·연 구독 (콘텐츠·기능 차이) | 가정 |
| 가격과 제공량 | 월 4,900원 / 연 39,000원 **[가안]** | 운영자 결정 |
| 로고·색상 | 밤 배경 + 용암 주황(#ff6a3d), 화산 아이콘 | 시안 |
| 외부 연동 | 없음 (결제·메일은 테스트 상태) | 결정 필요 |
| 운영자 정보 | `server/config.js` 의 `operator` | 입력 필요 |
| 기존 코드 | `breath/index.html` 호흡 화면을 웹앱에 이식 | 재사용 |
| 이번 범위 | MVP 구현 | |

**원가 판단:** 호흡 안내·음성·음악은 모두 사용자 기기에서 실행되어 세션당 외부 처리 비용이 0원입니다. 그래서 이용량 판매보다 콘텐츠·기능 차이로 과금하고, 무료 하루 3회는 서버에서 차감해 유료 전환 계기로 씁니다.

## 구조

```
server/
  config.js    앱별 설정: 이름·색·요금제·제공량·가격·운영자 정보 (다른 앱은 여기와 public/app 만 교체)
  db.js        SQLite 스키마
  auth.js      비밀번호(scrypt)·세션 쿠키·재설정 코드        ┐
  billing.js   결제/구독 분리, 이용권 계산, 웹훅 처리, 테스트 결제사 │ 공통 모듈
  usage.js     호흡 세션 시작·종료, 하루 이용량 차감·복원      │
  api.js       회원·세션·보관함·결제·문의 API, 관리자 API      ┘
  site.js      소개 사이트·약관·사이트맵·robots
  index.js     HTTP 서버, 보안 헤더, 정적 파일
public/app     웹앱 (breath.js = 호흡 엔진, app.js = 로그인·보관함·결제 셸)
public/admin   관리자 화면
test/          서버 테스트
```

### 결제·이용권 규칙

- 결제(payments)와 구독(subscriptions)과 이용 권한(entitlement)을 따로 관리합니다. 권한은 매 요청마다 서버가 구독 기간·상태와 관리자 지급 이용권으로 계산합니다.
- 권한은 결제 완료 화면이 아니라 **서명 검증된 결제 알림(웹훅)** 을 처리할 때만 생깁니다. 금액이 주문과 다르면 거절합니다.
- 같은 알림이 두 번 와도 이벤트 ID로 한 번만 처리합니다. 발생 시각이 이미 반영된 알림보다 이른 알림은 무시합니다(순서 뒤바뀜 대비).
- 상태: `active`(이용 중) · `canceled`(해지 예약, 기간 끝까지 이용) · `past_due`(갱신 실패, 3일 유예) · `expired`(만료) · `refunded`(환불, 즉시 종료).
- 이용량: 세션 시작 시 `UPDATE … WHERE used < limit` 한 문장으로 차감해 동시 요청에도 한도를 넘지 않습니다. 30초 안에 그만두면 되돌리고, 그 뒤엔 1회로 계산합니다. 한국 시간 자정 초기화, 이월 없음.
- 테스트 모드: 앱의 "테스트 결제" 화면과 관리자 "갱신 성공/실패·만료·환불" 버튼이 실제 웹훅과 같은 경로로 서명된 알림을 보냅니다. 모든 화면과 데이터에 테스트 표시가 붙습니다.

### 보안·개인정보

- 비밀번호 scrypt 해시, HttpOnly·SameSite 쿠키, 상태 변경 요청에 `X-Requested-With` 헤더 요구(CSRF), 로그인 시도 제한, CSP.
- 모든 기록 조회·수정·삭제는 `user_id` 조건으로 막아 다른 사람 자료에 접근할 수 없습니다(테스트 포함).
- 관리자 화면과 오류 기록에 사용자 메모가 남지 않습니다. 관리자 변경은 사유와 함께 운영 기록에 남습니다.
- 탈퇴 시 계정·기록 즉시 삭제, 결제 기록은 계정 연결을 끊고 보관.

## 출시 전 할 일 (운영자 결정·제공 필요)

1. **결제사 연결**: 토스페이먼츠 등 PG 계약 → `billing.js` 에 실결제 어댑터(결제창 호출, 승인 API, 자동결제 빌링키, 웹훅 서명 방식) 추가, `BILLING_MODE=live`. 앱스토어 출시 시 인앱결제 정책 별도 검토.
2. **메일 발송**: 현재 비밀번호 재설정·문의 답변 메일은 관리자 "메일함"에만 쌓입니다. 메일 서비스 연결 필요.
3. **가격 확정**과 `config.prices.draft=false`.
4. **운영자 정보·약관**: `config.js` 의 `operator`, 환불 기준, 위탁 업체, 보관 기간 입력 후 법률 검토.
5. **배포**: HTTPS 도메인, `COOKIE_SECURE=1`, 긴 `WEBHOOK_SECRET`, `PUBLIC_URL`, DB 파일이 남는 디스크(또는 Postgres 이전)와 백업 일정.
6. 선택: 카카오 간편 로그인, iOS/Android 포장, 주간 리포트.
