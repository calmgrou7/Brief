# 1분 견적 — 견적서·영수증 1분 생성 앱 기획서

> 이 문서는 **Codex(코딩 에이전트)가 그대로 따라 구현**하도록 쓴 실행 명세다.
> 마일스톤(§12) 단위로 하나씩 Codex에 맡기고, 각 단계의 완료 조건을 확인한 다음 다음 단계로 넘어간다.
> 가칭: **1분 견적** · 기준일: 2026-11-09

---

## 1. 한 줄 정의

프리랜서와 1인 사장님이 **거래처와 품목을 고르기만 하면 견적서, 거래명세서, 청구서, 영수증 PDF를 1분 안에 만들어 카톡으로 보내는** 모바일 우선 웹앱(PWA). 수익은 월 구독으로 낸다.

## 2. 문제와 기회 (1인 사업자 관점)

| 지금의 불편 | 1분 견적의 해결 |
|---|---|
| 엑셀·한글 양식을 매번 복사하고, 금액과 부가세를 손으로 계산하다 틀린다 | 품목을 넣으면 공급가액, 세액, 합계, 한글 금액(일금 ○○원정)을 자동으로 계산한다 |
| 내 사업자 정보, 계좌, 도장을 매번 다시 붙인다 | 한 번 저장하면 모든 문서에 자동으로 들어간다 |
| 견적서를 다시 영수증이나 청구서로 옮겨 적는다 | **원클릭 변환**: 견적서 → 거래명세서 → 청구서 → 영수증 |
| PC가 있어야 문서를 만든다 | 폰에서 만들고 PDF로 바로 카톡 공유한다 |
| 보낸 견적을 상대가 봤는지, 수락했는지 모른다 | 공유 링크로 **열람 알림과 수락 버튼**을 제공한다 (Pro) |
| 문서 번호와 이력 관리가 엉망이다 | 문서 번호를 자동으로 매기고, 거래처별 이력을 검색할 수 있다 |

- **유료 전환 근거**: 문서 1건이 곧 매출 1건이라서, 사용자가 이 도구로 돈을 번다는 체감이 크다.
- **바이럴 경로**: 무료 PDF의 워터마크가 받는 사람에게 노출되는데, 받는 사람도 대부분 사업자다.
- **첫 고객은 나**: 기획자 본인이 실제 업무에 쓰면서(dogfooding) 매주 개선점을 백로그에 넣는다.

## 4. 기술 스택 (결정 사항)

이 앱은 구독, 동기화, 공유 링크가 필요해서 서버가 있는 구성으로 간다.

| 영역 | 선택 | 이유 |
|---|---|---|
| 프레임워크 | **Next.js 15 (App Router) + TypeScript** | Codex가 가장 잘 다루고, 랜딩/SEO와 앱을 한 저장소에서 처리할 수 있다 |
| UI | Tailwind CSS + shadcn/ui | 빠른 구현과 일관성 |
| 백엔드 | **Supabase** (Auth, Postgres, Storage, RLS) | 1인 운영, 무료로 시작, 서버 코드 최소화 |
| 로그인 | 카카오와 이메일 매직링크 (Supabase Auth) | 타깃이 카카오에 익숙하다 |
| PDF | `@react-pdf/renderer` + **Pretendard** 폰트 임베드 | 브라우저 인쇄와 달리 기기마다 결과가 같다 |
| 결제 | **토스페이먼츠 빌링(정기결제)** | 국내 카드 정기결제, 웹훅 지원 |
| 호스팅 | Vercel | git push만으로 배포된다 |
| 테스트 | Vitest(단위), Playwright(E2E 핵심 흐름 1~2개) | |
| 오프라인 | PWA. 비로그인 무료 사용자는 IndexedDB에 저장 | 가입하지 않고도 바로 써보게 해서 전환 장벽을 낮춘다 |

**설계 원칙**: 계산과 포맷 로직은 `lib/calc/`의 **순수 함수**로만 둔다. UI, PDF, 서버가 모두 같은 함수를 쓴다.

## 7. 계산 명세 (`lib/calc/*`, 순수 함수)

### 7.1 품목과 합계 (`totals.ts`)

```ts
type TaxMode = 'exclusive' | 'inclusive' | 'exempt';
// exclusive: 부가세 별도 (단가는 공급가)
// inclusive: 부가세 포함 (단가에 세금 포함)
// exempt:    면세 또는 간이과세 (세액 0)

interface Line { name: string; spec?: string; qty: number; unitPrice: number; }
interface Input { lines: Line[]; taxMode: TaxMode; discount?: number; } // discount: 원, 세전 차감

interface Totals {
  lineAmounts: number[]; // 각 줄 금액
  subtotal: number;      // Σ 줄 금액
  discount: number;
  supply: number;        // 공급가액
  tax: number;           // 세액
  total: number;         // 합계
}
```

1. 줄 금액은 `Math.round(qty × unitPrice)`로 구한다. 수량은 소수 둘째 자리까지 허용한다(1.5시간 같은 경우).
2. `subtotal = Σ lineAmounts`, `base = subtotal − discount`. 할인이 소계보다 크면 에러다.
3. `exclusive`
   - `supply = base`
   - `tax = Math.floor(supply × 0.1)` (원 미만 절사)
   - `total = supply + tax`
4. `inclusive`
   - `total = base`
   - `supply = Math.floor(total × 10 / 11)`
   - `tax = total − supply`
5. `exempt`
   - `supply = total = base`
   - `tax = 0`
6. 세액은 **문서 합계 기준으로 한 번만** 계산한다. 줄마다 세액을 계산해서 더하지 않는다(반올림 오차 방지).
7. 금액은 모두 정수(원)이고, 음수 단가는 허용하지 않는다. 할인은 `discount` 필드로만 넣는다.

### 7.2 프리랜서 3.3% 원천징수 (`withholding.ts`)

- 적용: 청구서에 `withholding: true` 옵션을 켠 경우. 이때 세금 모드는 `exempt`로 고정한다(인적용역).
- 10원 미만 절사 함수: `floor10(x) = Math.floor(x / 10) × 10`
- 계산식
  - 소득세 = `floor10(total × 0.03)`
  - 지방소득세 = `floor10(소득세 × 0.1)`
  - 실지급액 = `total − 소득세 − 지방소득세`
- PDF에 "지급액 / 원천징수 3.3% / 실수령액" 3줄을 표시한다.

### 7.3 한글 금액 (`koreanAmount.ts`)

- 예: `1234500` → `일금 일백이십삼만사천오백원정`
- 형식 문서 관례에 따라 십·백·천 앞의 "일"을 **생략하지 않는다**(일십, 일백, 일천).
- 지원 단위는 만, 억, 조다. 0원이면 `일금 영원정`.

### 7.4 사업자등록번호 검증 (`bizNumber.ts`)

- 입력에서 하이픈을 제거하고 10자리 숫자인지 확인한다.
- 가중치 `[1,3,7,1,3,7,1,3,5]`
- `sum = Σ d[i] × w[i]` (i = 0~8), 여기에 `floor(d[8] × 5 / 10)`를 더한다.
- `(10 − sum % 10) % 10 === d[9]`이면 유효하다.
- 실패하면 막지 않고 **경고만** 한다(오타 방지 목적).
- 표시 형식은 `000-00-00000`.

### 7.5 문서 번호 (`docNumber.ts`)

- 형식: `{Q|S|I|R}-{YYYY}-{0001}`
- 사용자별, 유형별, 연도별로 순번을 매긴다. 연도가 바뀌면 0001부터 다시 시작한다.
- 사용자가 직접 수정할 수 있고, 같은 사용자 안에서 중복이면 경고한다.

## 9. 화면과 UX 명세

모바일 360px 우선이고 다크모드를 지원한다. 하단 탭은 `홈 · 새 문서(+) · 거래처 · 설정`이다.

1. **온보딩 (최초 1회, 3단계 이내)**
   - 1단계: 상호, 대표자, 연락처를 입력한다. 사업자번호는 선택이다(프리랜서 고려).
   - 2단계: "나는 프리랜서 / 사업자(일반과세) / 간이·면세"를 고르면 기본 세금 모드가 정해진다.
   - 3단계: 바로 첫 견적서 작성으로 넘어간다. 계좌, 로고, 도장은 나중에 설정에서 넣는다.
2. **홈**
   - 최근 문서 목록과 상태 배지(작성 중 / 발송 / 열람 / 수락 / 입금완료)를 보여준다.
   - 검색과 유형 필터를 둔다.
   - 이번 달 사용량을 "무료 3/5건"처럼 표시한다.
3. **문서 작성** (단일 화면, 위에서 아래 순서)
   - 유형 탭
   - 거래처 선택: 최근 거래처 칩과 새로 추가
   - 품목 입력: 품목 라이브러리 자동완성, 최근 품목 칩
   - 세금 모드
   - 할인과 메모
   - 문서 유형별 필드
   - 하단 고정 바: `합계 ₩660,000 · [미리보기] [PDF 공유]`
   - **입력하는 즉시 자동 저장**한다(작성 중 상태).
4. **미리보기**: 실제 PDF와 같은 레이아웃을 A4 비율로 보여준다. 위쪽에 `[유형 변환 ▾] [복제] [공유 링크]`를 둔다.
5. **공유**
   - Web Share API가 있으면 PDF 파일로 공유한다(카톡 첨부).
   - 없으면 다운로드한다.
   - Pro에서는 공유 링크를 복사할 수 있다.
6. **고객용 링크 `/d/[token]`**
   - 로그인 없이 열린다. 문서 보기와 PDF 다운로드를 제공한다.
   - Pro에서는 `[견적 수락]` 버튼을 둔다. 이름을 입력하고 체크하면 수락된다.
   - 열람과 수락 시 발행자에게 알림을 보낸다(이메일, 웹 푸시).
7. **설정**
   - 내 사업자 정보, 기본 세금 모드, 기본 유효기간, 계좌, 로고(PNG), 도장 이미지(배경 제거 안내)
   - 문서 하단 문구 템플릿
8. **PDF 템플릿**
   - 기본 1종을 제공하고, Pro에서 추가 2종과 브랜드 색상 지정을 연다.
   - A4 세로, Pretendard 폰트, 표에 줄무늬를 넣는다.
   - 합계 박스에 한글 금액과 숫자 금액을 같이 표시한다.

- 문서를 발행하면 그 시점의 공급자와 거래처 정보를 `*_snapshot`에 **얼려서 저장**한다. 나중에 설정을 바꿔도 과거 문서는 바뀌지 않는다.

**전환 장치**
- 4번째 문서를 만들면 "이번 달 무료 1건 남았어요"를 알려준다.
- 한도에 도달하면 업그레이드 시트를 띄운다. 첫 결제 7일은 무료 체험이다.
- 워터마크에는 랜딩 링크와 추천 코드를 넣는다. 추천으로 가입하면 양쪽에 Pro 1개월을 준다.
- 연간 결제를 기본으로 선택해 두고 "2개월 무료"를 강조한다.

**결제 흐름 (토스 빌링)**
1. 카드를 등록하고 billingKey를 발급받는다. billingKey는 서버에서 암호화해서 저장한다.
2. 즉시 첫 결제를 한다.
3. 매일 cron(Vercel Cron 또는 Supabase pg_cron)이 `current_period_end`가 오늘인 구독을 자동 결제한다.
4. 결제에 실패하면 3일 간격으로 2회 재시도하고, 그래도 실패하면 무료로 다운그레이드한다. 데이터는 보존한다.
5. 웹훅으로 상태를 동기화한다. 해지는 다음 결제일부터 적용한다.

## 13. 자동화 (1인 운영 시간 최소화)

1. **CI**: PR마다 `pnpm lint && pnpm test`를 돌리고, main 브랜치에서는 Playwright 스모크 테스트도 돌린다(GitHub Actions).
2. **배포**: main에 push하면 Vercel에 자동 배포되고, PR마다 프리뷰 URL이 생긴다.
3. **DB 마이그레이션**: `supabase/migrations`에 SQL을 두고, 배포 Action에서 `supabase db push`를 실행한다.
4. **구독 결제 cron**: 매일 09:00 KST에 실행하고, 실패 건은 운영자에게 이메일로 요약을 보낸다.
5. **주간 KPI 메일**: 매주 월요일 Supabase 함수로 아래 지표를 집계해서 나에게 보낸다.
   - 신규 가입
   - 생성 문서 수
   - 무료→Pro 전환
   - 해지
   - MRR
6. **오류 모니터링**: Sentry 무료 플랜을 쓴다.

## 15. 법·세무 주의사항 (UI 안내 문구 포함)

- 이 앱의 영수증과 거래명세서는 **세법상 적격증빙(세금계산서, 계산서, 카드전표, 현금영수증)이 아니다.**
  - 영수증 화면에 "3만원 초과 거래는 적격증빙이 필요할 수 있어요" 툴팁을 둔다.
- 전자세금계산서 발행은 MVP 범위가 아니다. 대신 "홈택스에서 발행하세요" 안내 링크를 둔다. 후속 Biz 플랜에서 API를 연동한다.
- 간이과세자 중 연매출 4,800만원 미만은 세금계산서를 발행할 수 없다. 온보딩에서 간이·면세를 고르면 기본값을 `exempt`로 둔다.
- 3.3%는 인적용역 사업소득 기준이다. 정확한 세무 판단은 세무사에게 확인하라는 고지를 둔다.
- 개인정보: 거래처 연락처를 저장하므로 개인정보처리방침과 이용약관 페이지가 필요하다(M7).
- 결제: 정기결제 고지(금액, 주기, 해지 방법)와 결제 전 동의 체크박스를 둔다.
