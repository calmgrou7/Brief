# 정책자금 컨설팅 업체 관리 — 데이터 정리안 v0.1

> 목적: 위들리, 개인 네트워크 컨설팅 업체, 앞으로 다른 경로로 들어올 업체를 **하나의 틀**로 모으고, 이를 바탕으로 대시보드를 만들어 관리한다.
> 원칙: **입력은 한 번만, 나머지는 자동으로.** 사람이 직접 넣는 항목은 최소화하고, 조회·계산 가능한 항목은 자동화 대상으로 표시한다.

---

## 0. 전체 구조

업체가 어느 경로로 들어오든 같은 **업체 마스터**에 한 줄로 쌓이고, 나머지 정보는 업체ID로 연결한다.

```
                ┌──────────────┐
  유입경로       │  ① 업체 마스터  │  ← 모든 업체 공통 (1업체 = 1행)
 (위들리/개인/   └──────┬───────┘
  소개/광고…)          │ 업체ID
        ┌─────────────┼──────────────┬──────────────┬─────────────┐
        ▼             ▼              ▼              ▼             ▼
  ② 담당자      ③ 역량 프로필    ④ 거래 조건     ⑤ 검증·리스크    ⑥ 활동 로그
  (1:N)          (1:1)          (1:1, 이력)     (1:1, 주기점검)   (1:N)
                                                                  │
                                       ⑦ 연결 건(케이스) ◀────────┘
                                       (내가 업체에 넘긴 고객 건, 1:N)
                                                  │
                                                  ▼
                                       ⑧ 대시보드 지표 (자동 계산)
```

| # | 테이블 | 언제 채우나 | 필수 단계 |
|---|---|---|---|
| ① | 업체 마스터 | 업체를 처음 알게 된 순간 | **1단계 (필수)** |
| ② | 담당자 | 첫 접촉 시 | **1단계 (필수)** |
| ③ | 역량 프로필 | 첫 미팅 후 | 2단계 |
| ④ | 거래 조건 | 제휴 협의 시 | 2단계 |
| ⑤ | 검증·리스크 | 활성화 전 + 분기 1회 | 2단계 |
| ⑥ | 활동 로그 | 연락할 때마다 | 운영 |
| ⑦ | 연결 건(케이스) | 고객을 넘길 때마다 | 운영 |
| ⑧ | 지표 | 자동 계산 | 대시보드 |

> **1단계만 채워도 대시보드가 돌아가게** 설계했다. 2단계 이후는 업체와 관계가 깊어질수록 채운다.

## ⑤ 검증·리스크 체크 — 활성화 전 + 분기 1회

정책자금 분야는 **제3자 부당개입(불법 브로커)** 이슈가 있어, 내가 고객을 넘기는 업체가 문제를 일으키면 내 신뢰도도 함께 떨어진다. 활성 상태로 올리기 전 최소 체크리스트를 둔다.

| 체크 항목 | 형식 | 방식 | 기준 |
|---|---|---|---|
| 사업자 상태 정상 | 예/아니오 | 🤖 국세청 API | "계속사업자" |
| 서면 계약서 사용 | 예/아니오 | ✍️ 계약서 샘플 확인 | 고객과 서면 계약 |
| 과도한 수수료 여부 | 예/아니오 | ✍️ | 업계 통상 범위 초과 시 경고 |
| 허위 보장 문구 | 예/아니오 | ✍️ 홈페이지·광고 확인 | "100% 승인", "정부 공식" 등 표현 |
| 기관 사칭 여부 | 예/아니오 | ✍️ | 공공기관 연계/공식 파트너 사칭 |
| 자격 확인 | 예/아니오 | ✍️ 자격증 사본 | ③ 보유 자격과 일치 |
| 분쟁·민원 이력 | 텍스트 | ✍️ 검색 + 평판 | |
| 개인정보 처리 동의서 | 예/아니오 | ✍️ | 고객 정보 넘길 때 필수 |
| 리스크 등급 | 선택 | 🤖 자동 | 낮음 / 주의 / 높음 (항목 결과로 계산) |
| 최근 점검일 / 다음 점검일 | 날짜 | 🤖 | +90일 자동 |

**규칙**: 리스크 등급 "높음"이면 진행 상태를 `활성`으로 바꿀 수 없음(검증 단계에서 막음).

## ⑦ 연결 건(케이스) — 성과 데이터의 원천

내가 업체에 넘긴 고객 1건 = 1행. **대시보드 수치는 대부분 여기서 나온다.**

| 필드 | 형식 | 설명 |
|---|---|---|
| 케이스ID | 자동 | `CS-2026-001` |
| 업체ID | 연결 | 수행 업체 |
| 고객사명 | 텍스트 | (개인정보 최소화 — 상호만) |
| 고객 업종 / 지역 / 업력 | 선택 | ③과 같은 코드표 사용 → 매칭 정확도 분석 |
| 신청 자금 종류 | 선택 | ③ 전문 자금 분야 코드 |
| 신청 금액 | 금액 | |
| 연결일 | 날짜 | |
| 단계 | 선택 | 연결 → 상담 → 계약 → 서류준비 → 접수 → 심사 → **승인 / 부결 / 고객이탈** |
| 단계 변경일 | 날짜 | 🤖 단계 바뀔 때 자동 기록 (소요기간 계산) |
| 승인 금액 | 금액 | |
| 부결·이탈 사유 | 선택+텍스트 | 신용 / 업력 / 서류 미비 / 한도 소진 / 고객 변심 / 업체 대응 불량 |
| 업체 수수료(고객 청구액) | 금액 | |
| 내 수익 | 금액 | 🤖 ④ 조건으로 자동 계산 |
| 정산 상태 | 선택 | 미청구 / 청구 / 입금완료 / 지연 |
| 정산 예정일 / 입금일 | 날짜 | 🔔 지연 알림 |
| 고객 만족도 | 1~5 | 종료 후 설문(자동 발송 후보) |

## ⑧ 대시보드 지표 (자동 계산)

| 구분 | 지표 | 계산 |
|---|---|---|
| 전체 현황 | 업체 수 (상태별·유입경로별) | ① 집계 |
| | 이번 달 신규 유입 업체 | ① 유입일 |
| 경로 비교 | **유입경로별 활성 전환율** | 활성 업체 ÷ 유입 업체 — 위들리 vs 개인 vs 기타 |
| | 유입경로별 매출 기여 | ⑦ 내 수익 합계 |
| 업체 성과 | 연결 건수 / 승인율 | ⑦ 승인 ÷ (승인+부결) |
| | 평균 승인 금액 | ⑦ |
| | 평균 소요기간 | ⑦ 연결일 → 승인일 |
| | 고객 이탈률 | ⑦ |
| 돈 | 이번 달 예상 수익 / 입금 수익 / 미수금 | ⑦ 정산 상태 |
| 관리 알림 | 계약 만료 임박, 리스크 점검 기한, 정산 지연, 30일 무활동 업체 | ④⑤⑥⑦ |
| 등급 점수 | 승인율 40% + 수익 기여 25% + 소요기간 15% + 만족도 10% + 리스크 10% | → S/A/B/C 제안 |

## 정보 수집 방법 — 무엇을 자동화하나

| 수집 대상 | 1차 방법 | 자동화 방안 |
|---|---|---|
| 신규 업체 기본정보 (①②③) | **업체 등록 폼 1개** (구글폼/Tally) 링크를 업체에 보내 직접 작성 | 폼 제출 → 시트/DB 자동 적재 → 업체ID 발급 |
| 위들리 경로 업체 | 위들리에서 받는 목록/정보 | 받은 형식 그대로 매핑 규칙 정해 일괄 업로드 (위들리 데이터 형식 확인 필요) |
| 사업자 상태·과세유형 | 사업자번호 입력 | 공공데이터포털 국세청 상태조회 API로 자동 채움 + 월 1회 재조회 |
| 홈페이지 문구 점검 (⑤) | 수기 확인 | 홈페이지 텍스트 수집 → 금칙 표현 자동 탐지 |
| 활동 로그 (⑥) | 수기 | Gmail·캘린더 연동으로 자동 생성 |
| 케이스·정산 (⑦) | 수기 (단계 변경만) | 단계 변경 시 날짜 자동 기록, 정산 지연 알림 |
