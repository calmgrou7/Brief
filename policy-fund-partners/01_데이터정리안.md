# 채움파트너스 정책자금 업무관리 — 데이터 정리안 v0.2

> **목적**: 위들리·플랭크·기타 소개처와 내가 직접 관리하는 업체에서 들어오는 **정책자금 고객사**를 한곳에 모으고, 단계별 진행 상황과 수수료를 놓치지 않고 관리하는 **내부 업무용 대시보드**를 만든다.
> **원칙**: 입력은 한 번만 하고, 날짜 기록·계산·알림은 자동으로 처리한다. 대시보드를 열면 **오늘 무엇을 해야 하는지**가 먼저 보이게 한다.

---

## 0. 업무 흐름과 데이터 구조

```
 [소개처]                                    [채움파트너스 업무]
 위들리 ─┐
 플랭크 ─┼─▶ 접수 폼 ─┐
 기타   ─┘            ├─▶ ② 고객사 ─▶ ③ 진행건 ─▶ 0 접수
 채움 직접 ─▶ 직접 등록┘   (기업 정보)   (자금 1건)    1 1차 미팅
                                                       2 자료 받기   ◀ ④ 서류 체크
                                                       3 진행 체크(신청·실사·심사)
                                                       4 자금 집행  ─▶ ⑥ 수수료 정산
                                                    ↘ 보류 / 반려 / 취소 / 거절
                                       ⑤ 활동 로그 (미팅·통화 기록, 다음 할 일)
```

| # | 테이블 | 한 행의 의미 | 누가 입력하나 |
|---|---|---|---|
| ① | 소개처 | 위들리, 플랭크, 채움 직접, 기타 업체 1곳 | 나 (가끔) |
| ② | 고객사 | 정책자금이 필요한 기업 1곳 | 소개처 접수 폼 / 내 직접 등록 |
| ③ | **진행건** | 고객사 × 자금 신청 1건 (**업무의 중심**) | 나 |
| ④ | 서류 체크 | 진행건별 필요 서류 1종 | 나 (체크만) |
| ⑤ | 활동 로그 | 미팅·통화·카톡 1회 | 나 |
| ⑥ | 수수료 정산 | 집행 1건에 대한 청구·입금 | 대부분 자동 |

> 고객사와 진행건을 나눈 이유: 한 기업이 중진공과 신보를 동시에 진행하거나, 거절된 뒤 다른 자금으로 다시 도전하는 경우가 많다. 기업 정보는 한 번만 입력하고, 자금별 진도와 수수료는 따로 관리한다.

## ① 소개처

| 필드 | 형식 | 설명 |
|---|---|---|
| 소개처ID | 자동 | `SRC-01` |
| 소개처명 | 텍스트 | 위들리 / 플랭크 / 채움파트너스(직접) / … |

| 담당자·연락처·이메일 | 텍스트 | 진행 보고와 정산 연락용 |
| 수수료 기준 | 선택 | 집행액 × % / 건당 고정액 / 별도 협의 |
| 수수료율·금액 | 숫자 | 예: 3% |
| 수수료 청구처 | 선택 | 소개처 / 고객사 직접 / 혼합 |
| 정산 시점 | 선택 | 집행 확인 후 / 월말 일괄 |

| 진행 보고 방식 | 선택 | 단계 변경 시 / 주간 / 요청 시 |

| 비고 | 텍스트 | |

> 수수료 조건이 바뀌면 덮어쓰지 않고 `적용 시작일`을 둔 새 행으로 남긴다. 그래야 과거 건의 정산 기준이 흔들리지 않는다.

| 최근 결산 영업이익 | 금액 | |
| 상시 근로자 수 | 숫자 | 4대보험 기준 |
| 대표자 신용점수 | 숫자 | NICE/KCB (동의를 받은 경우만) |
| 기존 정책자금·보증 잔액 | 금액 | 중진공 / 신보 / 기보 / 지역신보 각각 |
| 금융권 대출 잔액 | 금액 | |

| 보유 인증 | 다중선택 | 벤처 / 이노비즈 / 메인비즈 / 연구소 / 특허 / 여성·장애인기업 등 |
| 진단 의견 | 텍스트 | 가능 자금, 예상 한도, 리스크 |

## ③ 진행건 — 업무의 중심

### 단계와 상태를 분리한다

- **단계**: 어디까지 왔는가
- **상태**: 지금 진행 중인가, 멈췄는가

```
단계:  0 접수 → 1 1차 미팅 → 2 자료 받기 → 3 진행 체크 → 4 자금 집행
상태:  진행중 | 보류 | 반려 | 취소 | 거절 | 완료
```

| 상태 | 의미 (제안 — 바꿔도 됨) | 재개 |
|---|---|:-:|
| 진행중 | 정상 진행 | — |
| 보류 | 서류 대기, 시기 조정 등 일시 정지 | ○ |
| **반려** | 내가 검토한 뒤 **진행 불가로 판단** (체납, 신용, 업종 제외, 한도 초과 등) → 소개처에 돌려보냄 | △ 요건이 해소되면 |
| **취소** | **고객사나 소개처 사정**으로 중단 (연락 두절, 변심, 타사 진행) | ✕ |
| **거절** | **기관 심사에서 부결** | △ 다른 자금으로 새 진행건 생성 |
| 완료 | 4단계 자금 집행까지 끝남 | — |

> 반려·취소·거절은 **멈춘 단계**와 **사유 코드**를 반드시 남긴다. 그래야 "어느 단계에서, 왜 많이 떨어지는지"와 "소개처별 고객 품질"을 볼 수 있다.

### 필드

| 필드 | 형식 | 설명 |
|---|---|---|
| 진행건ID | 자동 | `P-2026-0001` |
| 고객사ID / 소개처ID | 연결 | 소개처는 고객사에서 자동으로 가져옴 |
| 대상 기관 | 선택 | 중진공 / 소진공 / 신보 / 기보 / 지역신보 / 지자체 / 은행협약 / 기타 |
| 자금명 | 텍스트 | 예: 혁신창업사업화자금, 일반경영안정자금 |
| 신청 예정 금액 | 금액 | |
| **단계** | 선택 | 0~4 |
| **상태** | 선택 | 위 표 |
| 3단계 세부 | 선택 | 신청서 작성 → 기관 접수 → 현장 실사 → 심사 중 → 승인 |
| 단계별 일자 | 날짜 ×5 | 🤖 단계를 바꾸면 그날 날짜가 자동 기록됨 (접수일, 1차 미팅일, 자료 완료일, 기관 접수일, 집행일) |
| 다음 할 일 | 텍스트 | 대시보드 "오늘 할 일"의 원천 |
| 다음 할 일 기한 | 날짜 | 🔔 기한 당일/초과 알림 |
| 승인 금액 | 금액 | |
| 집행 금액 / 집행일 | 금액 / 날짜 | 수수료 계산 기준 |
| 중단 단계 | 🤖 자동 | 반려·취소·거절 시점의 단계 |
| 중단 사유 | 선택 + 텍스트 | 코드표 참고 |
| 정체 일수 | 🤖 자동 | 마지막 단계 변경 후 지난 일수 → 14일 넘으면 경고 |
| 소개처 보고 여부 | 체크 + 날짜 | 단계가 바뀐 뒤 소개처에 알렸는지 |

## ④ 서류 체크 (2단계 자료 받기)

진행건을 만들면 **기본 서류 목록이 자동으로 생성**되고, 받을 때마다 체크한다. 기관마다 추가 서류가 있으면 행을 더한다.

| 기본 서류 | 비고 |
|---|---|
| 사업자등록증 | |
| 최근 3년 재무제표(표준재무제표증명) | 법인 / 개인 공통 |
| 부가세 과세표준증명 | |
| 국세·지방세 납세증명서 | 체납 확인 |
| 4대보험 가입자명부 | 상시 근로자 확인 |
| 대표자 신분증 사본 | |
| 법인등기부등본 / 주주명부 | 법인만 |
| 사업장 임대차계약서 | |
| 신용정보 조회 동의서 | |
| 사업계획서 | 내가 작성 / 보완 |

| 필드 | 형식 |
|---|---|
| 진행건ID / 서류명 | 연결 / 텍스트 |
| 상태 | 미요청 / 요청 / 수령 / 보완 필요 / 해당 없음 |
| 요청일 / 수령일 | 날짜 |
| 파일 위치 | 링크 (구글드라이브 폴더) |

> 🤖 서류가 전부 '수령'이 되면 2단계 완료 날짜가 자동으로 찍히고, 다음 할 일이 "신청서 작성"으로 바뀐다.

## ⑥ 수수료 정산

집행이 입력되면 🤖 **소개처의 수수료 기준으로 자동 계산**된다.

| 필드 | 형식 | 설명 |
|---|---|---|
| 정산ID / 진행건ID / 소개처ID | 자동 / 연결 | |
| 집행 금액 | 🤖 | ③에서 가져옴 |

| 청구처 | 🤖 | 소개처 / 고객사 |
| 상태 | 선택 | 청구 전 / 청구 / 입금 완료 / 지연 |
| 청구일 / 입금 예정일 / 입금일 | 날짜 | 🔔 예정일이 지나면 '지연'으로 바뀌고 알림 |
| 세금계산서 발행 | 체크 + 날짜 | |

## ⑦ 내 업무용 대시보드 구성 (초안)

**1. 오늘 할 일** (맨 위)
- 오늘이 기한이거나 기한이 지난 '다음 할 일'
- 14일 이상 정체된 진행건
- 서류 '보완 필요' 건
- 소개처에 아직 보고하지 않은 단계 변경

**2. 진행 보드** (칸반)
- 0 접수 │ 1 1차 미팅 │ 2 자료 받기 │ 3 진행 체크 │ 4 집행
- 카드: 기업명, 소개처, 기관, 금액, 정체 일수
- 보류·반려·취소·거절은 별도 탭

**3. 숫자 요약**
- 이번 달: 신규 접수 / 집행 건수 / 집행 금액 / 예상 수수료 / 입금된 수수료 / 미수금
- 진행 중 파이프라인 총액(신청 예정 금액 합)

**4. 소개처별 성과**
| 소개처 | 접수 | 진행중 | 집행 | 집행률 | 반려 비율 | 집행액 | 수수료 |
|---|---|---|---|---|---|---|---|
| 위들리 | | | | | | | |
| 플랭크 | | | | | | | |
| 채움 직접 | | | | | | | |
| 기타 | | | | | | | |

**5. 이탈 분석**
- 단계별로 남은 건수 (0→4 깔때기)
- 반려·취소·거절 사유 TOP 5 → 소개처에 "이런 업체는 보내지 말아 달라"는 사전 필터 기준으로 활용

## ⑧ 소개처용 접수 폼 (위들리·플랭크·기타)

소개처가 채워야 할 항목은 **최소한**으로 둔다. 길면 입력하지 않는다.

1. 소개처 (선택: 위들리 / 플랭크 / 기타 + 이름)
2. 소개처 담당자 이름·연락처
3. 기업명 / 사업자등록번호 / 대표자명 / 대표자 연락처
4. 개인·법인 / 소재지 / 업종 / 개업일
5. 희망 금액 / 자금 용도 / 희망 시기
6. 특이사항 (체납·연체 여부를 알면 입력)
7. ☑ 고객사로부터 정보 제공 동의를 받았음 (필수)

제출되면 🤖 고객사와 진행건(0단계·진행중)이 자동으로 생성되고, 사업자번호 중복 검사와 사업자 상태 조회가 실행된 뒤 나에게 알림이 온다.
내가 직접 관리하는 업체는 같은 폼에서 소개처를 `채움파트너스(직접)`로 골라 등록한다.
