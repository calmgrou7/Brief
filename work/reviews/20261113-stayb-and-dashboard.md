## A-2. 중점 (2) "가칭 / working name" 삭제에 대한 의견

1. **가칭 표기는 법적 보호 장치가 아니다.** "가칭"이라고 써도 남의 등록상표와 겹치면 침해 문제는 그대로이고, 지운다고 새로 생기는 법적 책임도 없다. 리스크의 본질은 "표기"가 아니라 "Stay B라는 이름을 상표 확인 없이 공개적으로 쓰는 것"이다.
2. **그래도 지금 지운 것은 이르다고 본다.** 이유: (a) 원천 자료(행정사에게 이미 보낸 제안서)는 "Stay B / Stay 부산은 가칭"이라고 명시한다. 같은 상대가 사이트를 보면 이름이 확정된 것으로 받아들인다. (b) 상표 검색을 하지 않았다(이 검토에서 웹 검색으로는 "STAY B" 등록 여부를 확인하지 못함. 키프리스(KIPRIS) 직접 검색 필요). "Stay"가 들어간 숙박·생활 서비스 상표가 많아 충돌 가능성이 낮지 않다. (c) 나중에 이름을 바꾸면 "가칭이었다"는 기록이 있는 편이 파트너·학생에게 설명하기 쉽다.
3. **권장안(대표 선택):**
   - 안 1(권장): 상표 확인 전까지 푸터 한 곳에만 `Stay B is a working name. / Stay B는 가칭입니다.`를 남긴다. 헤더·안내띠는 지금처럼 깔끔하게 둔다.
   - 안 2: 대표가 키프리스에서 "STAY B", "스테이비", "스테이 비"를 제35류(광고·사업 지원), 제41류(교육·정보), 제43류(숙소 정보), 제45류(법무·생활 지원) 위주로 확인한 뒤 가칭 표기 없이 간다.
   - 참고: 연계 브랜드 "Heritage Studio B"와 "B"가 겹치는 점은 같은 대표 소유라면 오히려 패밀리 브랜드로 유리하다.

# B. 회사 대시보드 `dashboard/index.html`

## 판정: 수정 요청

핵심: 데이터 연결이 안 된 상태(오프라인 보기·연결 중)에서도 숫자 `0`과 "결정할 일은 없어요", "프로젝트가 아직 없어요"가 떠서, 대표가 **"할 일이 없다"고 잘못 읽을 수 있다.** 그 외 보안·레이아웃은 양호.

## B-1. 실측 결과
- 콘솔 오류·경고 0건(400/1280 × 라이트/다크). 오프라인 보기 표시와 안내 문구 정상.
- 페이지 가로 스크롤 없음(400/1280). 400px에서는 업무 파이프라인만 상자 안에서 가로로 밀림(의도된 설계, `min-width:1040px`).
- 다크 모드 색 대비 문제 없음. 입력·버튼 높이 44px 이상.
- 지시 등록: 빈 칸이면 아무 일 없음, 오프라인이면 "저장할 수 없어요" 안내. 정상.
- 주의: 로컬 파일로 열면 한글이 전부 깨진다. 파일에 `<meta charset="utf-8">`이 없어서다. claude.ai 아티팩트는 UTF-8로 감싸 주므로 실제 화면엔 영향이 없을 가능성이 높지만, 한 줄 추가로 없앨 수 있는 위험이다(R-B1).

## B-2. 링크 안전성 (적합)
- 모든 데이터 출력은 `textContent`/`createElement`로 만들어 HTML 주입 경로 없음(`innerHTML` 미사용).
- 외부 링크는 `safeUrl`(`^https://`)을 통과한 것만 `<a target="_blank" rel="noopener">`로 만들고, 그 외 주소는 글자로만 표시(200·244·281행). `javascript:`·`http:` 링크 생성 불가 확인.
