## 4. 접근성·품질

| 항목 | 결과 |
|---|---|
| 접힘 묶음 키보드 | `summary`에서 Enter를 누르면 열리고 Space를 누르면 닫힌다. Tab 순서는 연락처 → summary → 학교 → 국적 → 언어 → 동의 → 보내기. 공통 `:focus-visible` 3px 외곽선이 적용된다. 필수 칸은 묶음 안에 없어서 오류가 숨겨진 칸에 생기지 않는다 |
| 고정 바 숨김과 스크린리더 | 숨길 때 `aria-hidden=true`와 링크 `tabindex=-1`이 함께 바뀌고, 포커스는 입력칸에 그대로 있다(가로채지 않음). 바가 숨는 것은 포커스가 입력칸에 있을 때뿐이라, 바 안 링크에 포커스가 있는 동안 숨는 경우는 없다. blur 50ms 뒤 원래 규칙으로 돌아간다 |
| 콘솔 오류·경고 | 0 (32조합과 페르소나 동선 전체) |
| 가로 스크롤 | 0 (32조합 모두 scrollWidth = 화면 폭) |
| 360×640 첫 화면 | 질문 링크 하단 EN 634px / KO 639px. 이전과 같고 첫 화면 안에 보인다 |
| 데스크톱 1280 | 접힘 묶음이 펼쳐진 상태로 나온다 |
| 링크 토스트 8초(R-3), 할인 카드 버튼(R-4) | 반영 |

## 5. 남은 이슈: 모바일 폼 높이 1,428px (실측, 접힌 상태)

- 의견: **기획자 판단은 지금 필요 없다(판정 영향 없음).** 목표 약 1,250px과의 차이 약 180px은 필수 5칸, 단계 버튼 5개(2열), 회신 방법 버튼 3개, 도움말 줄에서 나온다. 화면을 2화면에서 1.7화면으로 줄였고, 제출 버튼 위가 고정 바에 가려지지도 않는다. 데모 단계에서는 충분하다.
- 더 줄이려면 기획자 몫이다(나중에, 실제 서비스 전). 예: 만료일 칸을 단계가 "비자·졸업 이후"일 때만 보이게(약 120px 감소, 만료일 이어받기 동선은 visa라서 영향 없음) / 회신 방법 3개를 한 줄 3열로.
