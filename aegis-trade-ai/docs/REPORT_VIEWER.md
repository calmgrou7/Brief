# 오프라인 PAPER 보고서 웹뷰어

`report-viewer/index.html`을 로컬 브라우저에서 열면 사용할 수 있는 buildless HTML/JS입니다.
동일 디렉터리의 CSS/JS를 함께 유지하세요. 서버 API·계좌·시세 연결·매매 루프가 없습니다.
기존 합성 DEMO 사이트와 Python 매매 엔진은 변경하지 않았습니다.

1. `uv run python -m backend.app.paper_status --db public-paper.sqlite3 --format json > paper-report.json`
2. 화면에서 JSON 파일을 선택하거나 끌어 놓습니다(2MB 이하, 체결/거래 각 5,000건 이하).
3. 평가자산·실현/미실현 순손익·누적 수수료·마지막 시세·중단 사유·최신 100개 체결을 봅니다.
4. 비우기 버튼은 화면 메모리의 자료를 지웁니다. 파일은 자동 저장·업로드하지 않습니다.

기본 화면은 데이터 없음입니다. 예시 버튼은 기존 Python PaperSession을 fixture로 실행해
생성한 `MOCK` 기록만 표시합니다. 테스트 수익을 실제 성과로 표시하지 않습니다.
`PUBLIC_LIVE`도 파일의 출처 표기이며 이 화면에서 진위를 인증하거나 거래소에 접속하지
않습니다. 열람 시각에 신선도를 다시 계산합니다. 미래/누락 시각은 별도로 표시합니다.

금액은 십진 문자열 그대로 표시하고 브라우저 float로 재계산하지 않습니다. 내보낸 보고서의
대사 결과를 표시하며 기록을 실행 상태로 오인하지 않도록 고정 안내를 둡니다. 종료 후
미청산 포지션은 남고 가격·손절 감시가 중단됩니다. 가상 최종청산 비용은 미차감입니다.
파일의 모든 표시는 textContent로 처리하며 파일 안 HTML은 실행하지 않습니다.
CSP는 connect-src 'none'으로 앱의 네트워크 요청을 차단합니다. 외부 분석/폰트/CDN,
로컬 저장소, 업로드 경로가 없습니다. GitHub 링크는 사용자가 클릭하면 새 탭으로 열립니다.

## 검증

`make lint test build`: 기존 Python 83개 + Node 10개 테스트, Ruff/mypy/JS 문법/compile.
Node 테스트: Python 생성 MOCK 보고서 호환, 큰 십진수 정밀도/null/0, JSON·크기·스키마·
거래건수 검사, 현재시각 신선도, 출처 표시, 예시/비우기 DOM 상태, HTML 문자열 비실행,
잘못된 파일 때 기존 화면 유지, 비우기-파일읽기 경합 처리, 네트워크/저장 경로 부재.
DOM 테스트는 경량 unit harness이며 실제 브라우저 화면 QA를 대체하지 않습니다.

## 배포 상태와 제약 (2026-11-06)

현재 환경에서 Sites `site-workflow.mjs`/`set-project-id.mjs` 및 브라우저 QA 도구를
찾을 수 없어 사이트 소스 준비·패키징·배포와 시각적 QA를 완료하지 못했습니다.
관련 skill resource 경로를 통한 스크립트 조회도 실패했습니다. 새 Site를 만들거나
기존 Site 버전/접근권한을 변경하지 않았습니다. 이 문서는 배포 성공 증거가 아닙니다.

Sites 지원 환경에서는 기존 upbit Site의 소스와 owner-only 접근을 확인한 후, 기존
DEMO를 보존하면서 별도 `/reports/` 경로에 이 정적 디렉터리를 추가하는 방식을 권장합니다.
원본 Site 소스를 먼저 열어 충돌·라우팅을 검토하고 정상 helper로 패키징/게시해야 합니다.
이 변경도 Python 매매 프로세스 운영 배포와는 다릅니다.

실제 api.upbit.com은 현재 환경의 restricted 허용목록에 없어 요청 미시도입니다.
다른 호스트·프록시로 우회하지 않았으며 API 키·계좌·지속 서비스는 사용하지 않습니다.
