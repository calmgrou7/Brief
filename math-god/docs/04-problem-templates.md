# 04. MVP 문제 템플릿 20종

카테고리 5개 × 4종 = 20종. 템플릿 하나는 `src/lib/problems/templates/<id>.ts` 파일 하나로 구현한다.
각 항목의 **정답 공식**은 `generate()`에서, **검증 방법**은 `verify()`에서 쓴다(03 문서 §2 규칙).
"예시 정답"은 단위 테스트의 고정 케이스로 그대로 사용한다. 이 값들은 계산으로 확인했다.

표기: `d1~d5` = 난이도(별). 각 난이도에서 변수를 고르는 범위를 정한다. 지정하지 않은 난이도는 지원하지 않는다.

## A. 논리 추론 (logic)

### 1. `logic.fake-coin` — 가짜 동전 찾기
- **문제**: "겉모습이 똑같은 동전 {N}개 중 1개만 가짜이고 진짜보다 가볍다. 양팔 저울을 최소 몇 번 쓰면 가짜를 반드시 찾을 수 있을까?"
- **변수**: d1 N∈[3,9], d2 N∈[10,27], d3 N∈[28,81], d4 N∈[82,243]
- **d5 변형**: "가짜가 진짜보다 무거운지 가벼운지 모른다. 가짜를 찾고 무거운지 가벼운지도 알아내야 한다(기준 동전 없음)." N∈[4,39]
- **정답 공식**: d1–4 `ceil(log3 N)`. d5는 `(3^k − 3)/2 ≥ N`을 만족하는 최소 k
- **검증**: d1–4는 DP `f(1)=0, f(n)=1+min_{a≥1, 2a≤n} max(f(a), f(n−2a))`. d5는 알려진 결과 표(N≤3: 2, ≤12: 3, ≤39: 4) 대조
- **예시 정답**: N=9 → 2, N=10 → 3, N=243 → 5, d5 N=12 → 3, N=13 → 4
- **힌트**: ① 저울 한 번의 결과는 왼쪽, 오른쪽, 평형 3가지다 ② 3개 무리로 나눠 보자
- **생각의 핵심**: 저울 한 번은 후보를 3분의 1로 줄인다.

### 2. `logic.tournament` — 토너먼트 경기 수
- **문제**: "{N}명이 1:1 토너먼트(진 사람은 탈락, 부전승 있음)로 우승자 1명을 가린다. 총 몇 경기가 열릴까?"
- **변수**: d1 N∈{8,16,32}, d2 N∈[10,60] (2의 거듭제곱 제외), d3 N∈[100,999]
- **d4 변형**: 한 경기에 3명이 겨뤄 1명만 올라간다. N은 홀수이며 N∈[9,99]
- **d5 변형**: 한 경기에 k명(k∈{4,5})이 겨뤄 1명이 올라간다. N ≡ 1 (mod k−1)
- **정답 공식**: `(N − 1) / (k − 1)` (1:1이면 k=2)
- **검증**: 라운드를 시뮬레이션한다. 매 라운드 `floor(n/k)`경기를 치르고, 남은 인원은 부전승 처리한다. 1명이 남을 때까지의 경기 수를 합산한다(경기당 정확히 k명 조건은 생성 시 보장).
- **예시 정답**: N=16 → 15, N=37 → 36, d4 N=9 → 4, d5 k=4, N=10 → 3
- **힌트**: ① 경기 한 번마다 몇 명이 탈락할까? ② 우승자 빼고 모두 한 번씩 탈락한다
- **생각의 핵심**: 대진표를 그리지 말고 탈락자 수를 세라.

### 3. `logic.pigeonhole-socks` — 깜깜한 서랍
- **문제**: "불 꺼진 방의 서랍에 {k}가지 색 양말이 잔뜩 섞여 있다. 같은 색 {m}짝(=m개)을 반드시 얻으려면 최소 몇 개를 꺼내야 할까?"
- **변수**: d1 m=2, k∈{2,3}; d2 m=2, k∈[4,8]; d3 m=3, k∈[3,6]; d4 m∈[4,5], k∈[4,8]
- **d5 변형**: 색별 개수가 제한된다. 예: "빨강 {c1}개, 파랑 {c2}개, 검정 {c3}개". 이때 c_i 중 일부는 m−1보다 작다. m∈[3,5]
- **정답 공식**: `k(m−1)+1`. d5는 `Σ min(c_i, m−1) + 1`이며, 생성 시 `Σc_i ≥ 정답`이고 m개 이상인 색이 존재하도록 보장한다.
- **검증**: 최악의 경우를 탐욕적으로 시뮬레이션한다. 어떤 색도 m개에 도달하지 않게 최대한 꺼낸 개수에 1을 더한다(색별 개수 배열에서 직접 계산).
- **예시 정답**: k=3, m=2 → 4; k=5, m=3 → 11; d5 c=(2,10,10), m=4 → 2+3+3+1 = 9
- **힌트**: ① 가장 운이 나쁜 경우를 떠올려 보자 ② 모든 색이 m−1개씩 나온 직후를 생각해 보자
- **생각의 핵심**: "반드시"는 최악의 경우를 묻는 말이다.

### 4. `logic.doubling-jar` — 절반이 차는 순간
- **문제**: "병 속 미생물이 {s}분마다 {g}배로 늘어난다. 처음 1마리를 넣었더니 정확히 {T}분 뒤 병이 꽉 찼다. 병이 {1/g^j}만큼 찼던 때는 몇 분 뒤였을까?"
- **변수**: d1 g=2, s=1, j=1, T∈[30,120]; d2 g=2, s=1, j=2; d3 g=2, s∈{2,3,5}, j∈{1,2,3}; d4 g=3, s∈{1,2}, j∈{1,2}
- **d5 변형**: "처음에 {g^j}마리를 넣었다면 몇 분 만에 꽉 찰까?"
- **정답 공식**: `T − j·s` (d5도 동일)
- **검증**: 시간 0부터 s분 간격으로 개체 수를 정수로 시뮬레이션해서, 최종량 `g^(T/s)`의 1/g^j가 되는 시점을 찾는다. 생성 시 T가 s의 배수이고 T/s ≥ j가 되도록 보장한다. 큰 수는 BigInt를 쓴다.
- **예시 정답**: g=2, s=1, j=1, T=60 → 59; g=2, s=3, j=2, T=90 → 84; g=3, s=2, j=2, T=40 → 36
- **힌트**: ① 꽉 차기 바로 직전엔 얼마나 차 있었을까? ② 시간을 거꾸로 돌려 보자
- **생각의 핵심**: 거꾸로 생각하면 계산할 게 없다.

## B. 패턴 발견 (pattern)

### 5. `pattern.look-and-say` — 읽고 말하기 수열
- **문제**: "규칙을 찾아 다음 항을 쓰시오: {terms}, ?"
- **규칙**: 앞 항을 소리 내어 읽는다. 예: 1 → "1이 1개" → 11 → "1이 2개" → 21 → 1211 …
- **변수**: d1 시작=1, 4항 공개 후 5번째 질문; d2 시작∈{2,3}, 4항 공개; d3 시작=1, 5항 공개 후 6번째; d4 시작∈{2,3}, 5항 공개
- **d5 변형**: "7번째 항은 몇 자리 숫자인가?" 시작=1, 4항 공개 (정답 형식 integer)
- **정답 공식**: run-length 반복 구현(루프)
- **검증**: 정규식 `/(\d)\1*/g` 기반으로 따로 구현해 비교한다.
- **예시 정답**: 1, 11, 21, 1211 → 111221; 시작 1의 6번째 항 = 312211; 시작 1의 7번째 항 = 13112221 → 8자리
- **답 형식**: sequence (d5는 integer)
- **힌트**: ① 숫자를 크기가 아니라 '모양'으로 보자 ② 앞 항을 소리 내어 읽어 보자
- **생각의 핵심**: 수열이 꼭 계산일 필요는 없다.

### 6. `pattern.polynomial` — 숨은 차이
- **문제**: "다음 수열의 빈칸은? {t1}, {t2}, {t3}, {t4}, {t5}, ?"
- **변수**: `t(n) = a·n³ + b·n² + c·n + e`
  - d1: a=b=0, c∈[2,9], e∈[−5,10] (등차)
  - d2: a=0, b=1, c∈[−3,3], e∈[0,9]
  - d3: a=0, b∈{1,2}, c∈[−6,6], e∈[−5,9]
  - d4: a=0, b∈{2,3}, c∈[−9,9], e∈[−9,9]. 이때 6항까지 모든 항의 절댓값은 200 이하
  - d5: a=1, b=0, c∈[−3,3], e∈[−5,5]
- **정답 공식**: t(6)
- **검증**: 5개 항만으로 계차를 반복해 상수열이 될 때까지 내려간 뒤 다시 올라가며 6항을 외삽한다. d5는 3계차가 상수다.
- **예시 정답**: (a,b,c,e)=(0,1,0,0): 1,4,9,16,25 → 36; (0,2,−3,1): 0,3,10,21,36 → 55; (1,0,0,0): 1,8,27,64,125 → 216
- **힌트**: ① 이웃한 수끼리 빼 보자 ② 차이의 차이도 구해 보자
- **생각의 핵심**: 패턴이 안 보이면 차이를 보라.

### 7. `pattern.fibonacci-like` — 앞의 두 수
- **문제(d1–d3)**: "다음 수열의 빈칸은? {t1}, {t2}, {t3}, {t4}, {t5}, ?" (각 항은 앞 두 항의 합)
- **변수**: d1 t1,t2∈[1,5]; d2 t1,t2∈[3,15]; d3 각 항이 앞 **세** 항의 합이고 t1,t2,t3∈[1,5]
- **d4 변형(역추적)**: "각 항은 앞 두 항의 합이다. 3번째 항이 {t3}, 5번째 항이 {t5}일 때 1번째 항은?" (답이 양의 정수가 되도록 생성)
- **d5 변형**: "각 항은 앞 두 항의 합이다. 1번째 항이 {t1}, 6번째 항이 {t6}일 때 2번째 항은?" t1∈[1,9], t2∈[1,20]으로 t6을 만든다.
- **정답 공식**: 순방향 계산. d4는 `t4 = t5 − t3, t2 = t4 − t3, t1 = t3 − t2`. d5는 `t2 = (t6 − 3·t1) / 5`
- **검증**: d1–3은 반복문. d4, d5는 미지수를 1..100 전수 탐색해 조건을 만족하는 유일한 값을 찾는다(유일하지 않으면 생성 실패로 처리하고 다른 시드를 쓴다).
- **예시 정답**: 2,3,5,8,13 → 21; d5 t1=2, t6=41 → t2=7 (2,7,9,16,25,41)
- **힌트**: ① 앞의 수들과 어떤 관계일까? ② (d5) 6번째 항을 1번째, 2번째 항으로 표현해 보자
- **생각의 핵심**: 모르는 수를 문자로 두면 거꾸로도 풀린다.

### 8. `pattern.interleaved` — 두 개의 수열
- **문제**: "규칙을 찾아 빈칸을 채우시오: {t1}, {t2}, …, {t7}, ?"
- **규칙**: 홀수 번째 항과 짝수 번째 항이 각자 다른 규칙을 따른다.
- **변수**: d1 둘 다 등차(공차가 서로 다름); d2 홀수 등차, 짝수 등비(r=2); d3 홀수 등차, 짝수 등비(r=3); d4 홀수 등비(r=2), 짝수는 제곱수 열 n²; d5 세 수열이 번갈아 나옴(3칸 주기, 9항 공개 후 10번째 질문)
- 모든 항은 1000 이하
- **정답 공식**: 해당 위치 수열의 다음 항
- **검증**: 위치별로 부분수열을 추출하고, 각 부분수열을 독립적으로 등차/등비/제곱 판정해 외삽한다.
- **예시 정답**: d2 a=1, d=3 / b=2, r=2: 1,2,4,4,7,8,10 → 16
- **힌트**: ① 한 칸씩 건너뛰어 보자 ② 두 수열이 지퍼처럼 맞물려 있다
- **생각의 핵심**: 하나로 안 풀리면 둘로 나눠 보라.

## C. 공간·기하 직관 (geometry)

### 9. `geometry.clock-hands` — 시곗바늘
- **문제**: "아날로그 시계에서 0시 정각부터 {H}시 정각 직전까지, 시침과 분침이 {관계}인 순간은 몇 번 있을까? (0시 정각 포함)"
- **변수**: d1 관계=겹침, H∈{3,6}; d2 겹침, H∈{12,24}; d3 일직선(정반대), H∈{12,24}; d4 직각, H∈{6,12}; d5 직각, H=24
- **정답 공식**: 상대속도는 시간당 330°다. 순간들의 시각 t(시간)는 다음과 같다.
  - 겹침 `t = 12k/11`, 정반대 `t = (6+12k)/11`, 직각 `t = (3+6k)/11`
  - k ≥ 0 중 t < H인 것의 개수
- **검증**: 유리수(분자/분모 정수)로 0 ≤ t < H 구간에서 각도 함수 `(330t mod 360)`이 목표 각도를 지나는 시점을 1/1320시간 간격으로 탐색해 센다. 경계는 정수 비교로 정확히 처리한다.
- **예시 정답**: 겹침 H=3 → 3, H=6 → 6, H=12 → 11, H=24 → 22; 정반대 H=12 → 11; 직각 H=12 → 22, H=24 → 44
- **힌트**: ① 분침은 시침을 1시간에 정확히 한 바퀴씩 따라잡을까? ② 12시간 동안 분침은 11바퀴를 더 돈다
- **생각의 핵심**: 따라잡는 문제는 '차이'의 속도로 본다.
- **그림**: 시계 SVG(바늘 없이 숫자판만)

### 10. `geometry.polygon-count` — 다각형 세기
- **문제**: d1–3 "볼록 {n}각형의 대각선은 모두 몇 개?"; d4 "볼록 {n}각형의 꼭짓점 3개를 골라 만들 수 있는 삼각형은 몇 개?"; d5 "볼록 {n}각형의 대각선끼리 내부에서 만나는 점은 최대 몇 개? (세 대각선이 한 점에서 만나지 않음)"
- **변수**: d1 n∈[5,8], d2 n∈[9,15], d3 n∈[16,30], d4 n∈[6,12], d5 n∈[5,10]
- **정답 공식**: 대각선 `n(n−3)/2`, 삼각형 `C(n,3)`, 교점 `C(n,4)`
- **검증**: 꼭짓점 쌍, 세 쌍, 네 쌍을 이중/삼중/사중 루프로 전수 열거한다(교점은 네 점마다 대각선 교점 1개).
- **예시 정답**: n=6 대각선 9, n=10 대각선 35; n=8 삼각형 56; n=6 교점 15
- **힌트**: ① 한 꼭짓점에서 그을 수 있는 대각선은 몇 개? ② 두 번씩 셌다면 나눠 주자 / (d5) 교점 하나는 꼭짓점 몇 개로 정해질까?
- **생각의 핵심**: 하나를 세고, 중복을 나눠라.
- **그림**: 정n각형 SVG(대각선 없이)

### 11. `geometry.painted-cube` — 페인트 칠한 큐브
- **문제**: "가로·세로·높이가 {n}인 정육면체의 겉면을 모두 빨갛게 칠한 뒤, 1×1×1 작은 큐브로 잘랐다. 빨간 면이 정확히 {f}개인 작은 큐브는 몇 개일까?"
- **변수**: d1 f=3, n∈[3,10]; d2 f=2, n∈[3,8]; d3 f=1, n∈[3,7]; d4 f=0, n∈[3,8]
- **d5 변형**: 직육면체 a×b×c (a,b,c ∈ [3,7], 서로 다름), f∈{0,1}
- **정답 공식**: 정육면체 f=3: 8, f=2: 12(n−2), f=1: 6(n−2)², f=0: (n−2)³. 직육면체 f=0: (a−2)(b−2)(c−2), f=1: 2[(a−2)(b−2)+(b−2)(c−2)+(a−2)(c−2)]
- **검증**: 모든 단위 큐브 좌표 (x,y,z)를 순회하며 바깥면에 닿은 면 수를 센다.
- **예시 정답**: n=5: f=3 → 8, f=2 → 36, f=1 → 54, f=0 → 27; 3×4×5 f=0 → 6, f=1 → 2(2+6+3)=22
- **힌트**: ① 꼭짓점, 모서리, 면, 속에 있는 큐브로 나눠 보자 ② 겉을 한 겹 벗기면 어떤 크기가 남을까?
- **생각의 핵심**: 위치에 따라 분류하면 세지 않아도 된다.
- **그림**: 등각투상 큐브 SVG

### 12. `geometry.grid-paths` — 최단 경로
- **문제**: "바둑판 모양 길에서 왼쪽 아래 A에서 오른쪽 위 B까지 오른쪽 또는 위로만 간다. 가로 {m}칸, 세로 {n}칸일 때 가는 방법은 몇 가지?"
- **변수**: d1 (m,n)∈{(2,2),(2,3)}; d2 m,n∈[3,4]; d3 m,n∈[3,5]
- **d4 변형**: 공사 중인 교차점 1개를 지날 수 없다(모서리 제외, 경로 위의 점).
- **d5 변형**: 반드시 특정 교차점 P를 지나야 하고, 다른 교차점 1개는 통행 금지
- **정답 공식**: `C(m+n, m)`. d4는 `전체 − C(P까지)·C(P에서 B까지)`. d5는 P 경유 경로에서 금지점을 지나는 경로를 포함배제로 뺀다.
- **검증**: 격자 DP(`ways[i][j] = ways[i−1][j] + ways[i][j−1]`, 금지점은 0, 경유점은 두 구간 DP를 곱함)
- **예시 정답**: 2×2 → 6, 3×3 → 20, 5×5 → 252; 3×3에서 (1,1) 금지 → 20 − 2·6 = 8
- **힌트**: ① 각 교차점까지 가는 방법 수를 적어 보자 ② 어떤 점까지의 방법 수 = 왼쪽 점 + 아래 점
- **생각의 핵심**: 큰 문제를 작은 칸의 합으로 쪼개라.
- **그림**: 격자 SVG(A, B, P, 금지점 표시)

## D. 확률 직관 (probability)

### 13. `probability.monty-hall` — 문을 바꿀까?
- **문제**: "문 {n}개 중 하나 뒤에만 자동차가 있다. 당신이 문 하나를 고르자, 정답을 아는 사회자가 나머지 중 빈 문 {k}개를 열어 보여 준다. 이제 당신이 남은 다른 닫힌 문 중 하나로 (무작위로) 바꾼다면 자동차를 얻을 확률은?"
- **변수**: d1 n=3, k=1, 객관식("바꾸는 게 유리 / 그대로가 유리 / 똑같다"); d2 n=3, k=1, 분수; d3 n∈[4,6], k=n−2; d4 n∈[4,8], k∈[1,n−3]; d5 n∈[6,10], k∈[1,n−3]
- **정답 공식**: `(n−1) / (n·(n−k−1))`를 기약분수로 만든다.
- **검증**: 자동차 위치 n가지 × 첫 선택 n가지를 전수 열거한다. 사회자가 열 문의 조합은 가능한 경우에 균등 확률을 준다. 바꿀 문도 남은 문 중 균등하게 고른다. 유리수로 정확히 합산한다.
- **예시 정답**: n=3,k=1 → 2/3; n=4,k=2 → 3/4; n=4,k=1 → 3/8; n=10,k=8 → 9/10
- **힌트**: ① 처음 고른 문이 정답일 확률은 열린 문과 상관없이 그대로다 ② 나머지 확률은 어디로 갈까?
- **생각의 핵심**: 새 정보는 '내가 안 고른 쪽'의 확률을 바꾼다.

### 14. `probability.birthday` — 생일이 같은 사람
- **문제(d2–d4)**: "한 방에 생일이 같은 사람이 적어도 한 쌍 있을 확률이 {p}%를 넘으려면 최소 몇 명이 필요할까? (1년=365일, 모든 날짜 동일 확률)"
- **d1 변형**: "생일이 같은 사람이 **반드시** 한 쌍 있으려면 최소 몇 명?" (2월 29일 포함 366일) → 367
- **변수**: d2 p=50, 객관식 4지선다(예: 23 / 92 / 183 / 365); d3 p∈{70,90}, 객관식; d4 p∈{50,70,90,99}, 정수 입력
- **정답**: p=50 → 23, 70 → 30, 90 → 41, 99 → 57
- **검증**: `1 − Π_{i=0}^{n−1} (365−i)/365 > p/100`인 최소 n을 반복 계산한다(배정밀도로 충분).
- **오답 선택지 생성**: 정답과 함께 `365×p/100`의 반올림 값, 183, 정답×2 중에서 서로 다른 3개를 뽑는다.
- **힌트**: ① 특정한 '나'와 같은 생일이 아니라 '아무 두 명'이다 ② 23명이면 쌍이 몇 개나 될까? (253쌍)
- **생각의 핵심**: 사람 수가 아니라 '쌍'의 수가 확률을 키운다.

### 15. `probability.at-least-once` — 적어도 한 번
- **문제**: "확률이 1/{k}인 일(예: {예시})을 반복할 때, 적어도 한 번 일어날 확률이 {t}%를 넘으려면 최소 몇 번 시도해야 할까?"
- **예시 문구**: k=2 동전 앞면, k=6 주사위 6, k=10 열 장 중 당첨, k=20 20면체 주사위 20
- **변수**: 모두 객관식 4지선다(계산기 없이 '감'을 묻는 문제)
  - d1 k=6, t=50 ("6번 던지면 반드시 나온다" 착각을 겨냥)
  - d2 k∈{2,6}, t∈{50,90}
  - d3 k∈{10,20}, t=50
  - d4 k∈{6,10,20}, t=90
  - d5 k∈{6,10,20}, t=99
- **정답 공식**: `1 − ((k−1)/k)^n > t/100`인 최소 n
- **검증**: 독립 반복문 + 로그 공식 `ceil(log(1−t/100)/log((k−1)/k))`을 교차 확인한다(경계 동일값 주의, 엄격 부등호).
- **예시 정답**: k=6, t=50 → 4; k=6, t=90 → 13; k=20, t=50 → 14; k=2, t=99 → 7
- **오답 선택지**: k, k/2 반올림, 정답×2, 정답+k 중 서로 다른 3개(정답과 겹치면 다음 후보)
- **힌트**: ① "한 번도 안 일어날 확률"을 먼저 생각해 보자 ② 그 확률이 1−t% 아래로 떨어지는 때를 찾자
- **생각의 핵심**: '적어도 한 번'은 '한 번도 안 일어남'을 뒤집어서 푼다.

### 16. `probability.waiting-time` — 평균 몇 번?
- **문제**: d1–2 "{k}면체 주사위를 특정 숫자가 나올 때까지 던진다. 평균 몇 번 던지게 될까?"; d3 "동전을 던져 앞면이 두 번 **연속** 나올 때까지 평균 몇 번 던질까?"; d4–5 "{k}면체 주사위로 모든 숫자를 한 번 이상 볼 때까지 평균 몇 번 던질까?"
- **변수**: d1 k∈{2,4,6}; d2 k∈{8,10,12,20}; d3 고정; d4 k∈{2,3,4}; d5 k∈{5,6}
- **정답 공식**: 특정 숫자 `k`; 앞면 연속 2번 `6`; 모든 숫자 `k·(1 + 1/2 + … + 1/k)`
- **답 형식**: integer(d1–3), decimal 허용오차 0.1(d4–5)
- **검증**: d1–3은 마르코프 체인 기대값을 유리수 연립으로 계산한다. d4–5는 상태별 기대값 DP(`E[i] = k/(k−i) + E[i+1]`)로 계산하고, 몬테카를로 20만 회로 ±0.1 교차 확인한다.
- **예시 정답**: k=6 → 6; 앞면 연속 2번 → 6; 모든 숫자 k=2 → 3, k=3 → 5.5, k=4 → 8.33, k=5 → 11.42, k=6 → 14.7
- **힌트**: ① 새 숫자가 나올 확률은 남은 숫자 개수에 따라 바뀐다 ② 확률이 p인 일은 평균 1/p번 만에 일어난다
- **생각의 핵심**: 기다림을 단계로 나누면 각 단계는 쉽다.

## E. 어림 추정 (estimate)
계산기 없이 '어림'으로 푸는 문제다. 답 형식은 `estimate`이며 기본값은 fullFactor=2(정답), partialFactor=4(부분 정답)다.
제한 시간 60초 타이머를 보여 주지만, 시간이 초과돼도 제출은 가능하다(XP만 0.8배).
입력 UI에서 "천/만/억" 단위 버튼을 제공한다. 실세계 통계값처럼 출처가 필요한 사실은 쓰지 않고, 문제에 주어진 값이나 상식 상수만 사용한다.

### 17. `estimate.time-units` — 시간의 크기
- **문제**: d1 "1년은 대략 몇 초일까?"; d2 "{N}년은 대략 몇 초일까?" N∈{10,30,100}; d3 "10억 초는 대략 몇 년일까?"; d4 "{N}억 초는 대략 몇 년일까?" N∈{5,20,100}; d5 "1초에 1씩 쉬지 않고 1억까지 세면 대략 며칠 걸릴까?"
- **정답 공식(기준값)**: 1년 = 365×24×3600 = 31,536,000초. 10억 초 = 31.7년. 1억 초 = 1,157일
- **검증**: 일·시·분 단위로 따로 곱해 같은 값을 재계산한다.
- **힌트**: ① 하루는 약 9만 초(86,400) ② 1년은 약 3천만 초
- **생각의 핵심**: 큰 수는 '쉬운 덩어리'로 쪼개서 어림한다.

### 18. `estimate.paper-fold` — 종이 접기
- **문제**: "두께 0.1mm 종이를 반으로 {n}번 접을 수 있다면 두께는 대략 얼마일까? (단위: {unit})"
- **변수**: d1 n=10 (단위 cm, 기준 10.24cm); d2 n∈[15,20] (m); d3 n∈[25,30] (km); d4 n∈[35,40] (km); d5 n=42 (km, "달까지 거리 38만 km와 비교")
- **정답 공식**: `0.1mm × 2^n`을 해당 단위로 환산. n=42 → 약 439,805km
- **검증**: 2^10 ≈ 1024 덩어리로 나눈 계산과 직접 BigInt 계산을 비교한다.
- **힌트**: ① 10번 접으면 약 1,000배다 ② 2^10 ≈ 1,000, 2^20 ≈ 100만, 2^40 ≈ 1조
- **생각의 핵심**: 두 배씩 늘어나는 것은 상상보다 훨씬 빠르다.

### 19. `estimate.pingpong-room` — 방을 채우는 탁구공
- **문제**: "가로 {a}m, 세로 {b}m, 높이 {h}m 방을 지름 4cm 탁구공으로 가득 채우면 대략 몇 개가 들어갈까?"
- **변수**: d2 a=b=3, h=3(정육면체 방); d3 a,b∈[3,6], h=2.5; d4 a,b∈[5,10], h∈{2.5,3}; d5 "축구장(105m×68m)을 탁구공으로 1m 높이까지" 
- **정답 공식(기준값)**: `0.6 × 부피 / (π·0.04³/6)`. 무작위로 채울 때 충전율은 약 0.6이며, 단순 정육면체 배치 `부피/0.04³`도 fullFactor 이내에 들어온다.
- **예시**: 3×3×3m → 기준값 약 483,000개 (단순 계산 421,875개도 정답 처리)
- **검증**: 단위를 cm로 바꿔 독립 계산한다.
- **힌트**: ① 1m에는 탁구공이 몇 개 줄 서나? (25개) ② 1m³에는 약 25×25×25개
- **생각의 핵심**: 1차원으로 세고 세제곱하라.

### 20. `estimate.around-earth` — 지구 한 바퀴
- **문제**: "지구 둘레는 약 4만 km다. {수단}(시속 {v}km)으로 쉬지 않고 한 바퀴 돈다면 대략 며칠 걸릴까?"
- **변수**: d1 도보 v=5; d2 자전거 v∈{15,20}; d3 자동차 v∈{80,100}; d4 "하루 8시간만 걷는다면" v=4 (일수 = 40000/(4×8) = 1,250일); d5 "달팽이(시속 0.05km)" → 약 33,333일 → 단위를 '년'으로 묻는다(약 91년)
- **정답 공식**: `40000 / v / 24` (d4는 하루 이동 시간으로 나눔)
- **예시 정답**: 도보 시속 5km → 약 333일
- **검증**: 하루 이동거리(km/일)를 먼저 구한 뒤 나눠서 재계산한다.
- **힌트**: ① 하루에 몇 km를 가는지 먼저 구하자 ② 4만을 그 거리로 나누자
- **생각의 핵심**: 단위를 '하루'로 바꾸면 어림이 쉬워진다.

## 공통 구현 메모
- 본문, 힌트, 해설 문자열은 템플릿 코드 안에 `{param}` 자리표시자로 작성하고 `format()` 유틸로 채운다. AI 스킨이 있으면 본문만 스킨으로 대체한다.
- 객관식 선택지는 시드 기반으로 순서를 섞는다.
- 생성 실패(유일해 조건 불만족 등)는 `seed+1`로 최대 10회 재시도하고, 그래도 실패하면 예외를 던진다(테스트에서 발견해야 함).
- 템플릿을 추가할 때는 이 문서에 항목을 먼저 추가하고 구현한다.
