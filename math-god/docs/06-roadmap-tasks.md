# 06. 로드맵 & 작업 목록 (에이전트 실행 순서)

각 작업은 위에서부터 순서대로 진행한다. **완료 기준**을 모두 만족하고 `pnpm lint && pnpm typecheck && pnpm test`가 통과해야 다음 작업으로 넘어간다.
예상 기간은 1인 + 코딩 에이전트 기준이다.

---

## M0. 프로젝트 셋업 (0.5일)
**T0-1 Next.js 초기화**
- Next.js(App Router) + TypeScript strict + Tailwind + ESLint + Prettier + Vitest + Playwright를 pnpm으로 구성한다.
- 스크립트: `dev`, `build`, `lint`, `typecheck`, `test`, `test:e2e`, `gen:problems`
- 완료 기준: `pnpm build` 성공, 샘플 테스트 1개 통과, `.env.example` 존재(05 문서 §2)

**T0-2 Supabase 로컬 환경**
- `supabase init`, `supabase/migrations/0001_init.sql`(05 문서 §3), RLS 정책, 인덱스, `apply_attempt_result()` 함수
- `src/lib/supabase/{client,server,admin}.ts`
- 완료 기준: `supabase db reset` 성공. 익명 키로 `problem_answers`, `served_problems`를 select하면 0행이 나오는 테스트

---

## M1. 게임 규칙 엔진 (1일)
**T1-1 `src/lib/game/` 순수 함수**
- `constants.ts`, `xp.ts`, `level.ts`(레벨표, 칭호), `rating.ts`(Elo, 티어, 별 변환), `streak.ts`(KST 날짜 처리), `scoring.ts`(결과 + 힌트 → Elo score S)
- 완료 기준: 02 문서의 모든 예시값(XP 표, 누적 XP 기준값, 칭호 경계, 티어 경계)이 테스트로 존재하고 통과. 스트릭은 KST 자정 경계 테스트 포함

---

## M2. 문제 엔진 (3일)
**T2-1 기반**
- `types.ts`(03 문서 §2), `rng.ts`(mulberry32), `answer.ts`(03 문서 §3 판정, 한국어 단위 파싱: "48만", "1.2억", "3천"), `format.ts`, `registry.ts`
- 완료 기준: answer.ts 테스트(분수 동치, 소수 입력, 추정 정답/부분 정답/오답 경계, 전각 숫자)

**T2-2 템플릿 20종 구현** (04 문서)
- 카테고리별로 커밋한다(logic → pattern → geometry → probability → estimate).
- 템플릿마다 테스트: (a) 04 문서 예시 정답 고정 케이스 (b) 지원 난이도별 시드 1..1000에서 `generate().answer` == `verify(params)` (c) 결정성(같은 시드 = 같은 결과) (d) 숫자 범위 제약
- 기하 템플릿 SVG(clock, polygon, cube, grid)는 `figure`로 반환한다.
- 완료 기준: 20개 템플릿 전체 속성 테스트 통과, `registry.list()`가 20개 반환

**T2-3 개발용 미리보기 페이지** `/dev/templates` (개발 환경에서만)
- 템플릿, 난이도, 시드를 골라 문제, 정답, 힌트, 해설, SVG를 확인한다.
- 완료 기준: 20종 모두 렌더링 확인(Playwright 스냅샷)

---

## M3. 인증 & 핵심 풀이 루프 (4일)
**T3-1 인증**: 익명 로그인 자동 시작, 카카오/구글 연결, 닉네임 설정, 금칙어
- 완료 기준: 익명으로 문제를 풀고 → 구글 연결 → XP가 유지되는 E2E

**T3-2 서버 API**: `/api/session`, `/api/problem/next`, `/api/problem/hint`, `/api/problem/submit`, `/api/problem/report` (05 문서 §4–5)
- public payload 화이트리스트 직렬화
- 완료 기준: (a) 응답 JSON에 answer와 미공개 힌트가 없음을 검증하는 테스트 (b) 다른 사용자의 servedId로 제출하면 403 (c) 재도전 규칙 (d) 힌트 사용 후 XP 감소

**T3-3 풀이 UI**: `/practice`, `/play/[sessionId]`, `/result/[attemptId]`
- 답 형식별 입력 컴포넌트(숫자 키패드, 분수, 객관식, 추정 + 단위 버튼), 힌트 버튼(비용 표시), 메모장
- 결과: XP 카운트업 애니메이션, 레벨업 전체 화면 연출, 두뇌지수 ±, 해설, "생각의 핵심", 다음 문제
- 완료 기준: 모바일 뷰포트(390×844)에서 연습 10문제 연속 풀이 E2E

**T3-4 출제 알고리즘**(02 문서 §6)과 rating_buckets 초기 데이터(20 템플릿 × 지원 난이도) 시드 스크립트
- 완료 기준: 레이팅 1000인 사용자의 출제 난이도 분포 테스트(시뮬레이션 1,000회에서 별 2–3 비중 70% 이상)

## M4. 레벨 체크 · 오늘의 문제 · 랭킹 · 실시간 (4일)
**T4-1 두뇌 레벨 체크** `/check` (02 문서 §7) + 결과 카드 + 공유 이미지(`next/og`로 OG 이미지 생성)
- 완료 기준: 10문제 완료 → 두뇌지수, 티어, 백분위, 레이더가 표시된다. 공유 URL에서 OG 이미지가 렌더링된다.

**T4-2 오늘의 문제** `/daily` + `/api/cron/daily` + 순위 규칙(02 문서 §8)
- 완료 기준: 같은 날 두 사용자가 동일한 문제를 받는다. 1회 제출 제한. 자정 순위 확정과 배지 테스트

**T4-3 랭킹** `/ranking` 4탭 + 내 순위 하단 고정 + Realtime 구독(05 문서 §6)
- 완료 기준: 브라우저 2개 E2E에서 A가 문제를 맞히면 B의 오늘 랭킹 화면이 3초 안에 갱신된다.

**T4-4 홈 대시보드** `/home`: 오늘의 문제 카드, 레벨 진행 바, 스트릭, 두뇌지수, 레벨업 피드(Realtime), 접속자 수(Presence)
- 완료 기준: 칭호가 바뀌는 레벨업이 일어나면 다른 브라우저 홈 피드에 3초 안에 표시된다.

**T4-5 프로필** `/profile/[nickname]`: 칭호, 배지, 두뇌지수 추이(최근 30일), 카테고리 레이더, 정답률

**T4-6 스트릭 & cron**: 00:05 스트릭 처리, 보호권 자동 소모, 마일스톤 배지
- 완료 기준: 날짜를 모킹한 테스트(연속 / 하루 빠짐 + 보호권 / 하루 빠짐 + 보호권 없음)

## M5. AI 문제 생성 파이프라인 (3일)
**T5-1 생성기** `supabase/functions/generate-problems` + 로컬 실행 스크립트 `pnpm gen:problems --category logic --count 5 --dry-run`
- 재고 확인 → 생성(structured output) → 3중 검증(QuickJS 샌드박스, 독립 풀이 2회, 품질 판정) → 유사도 검사 → 저장 (03 문서 §4)
- 완료 기준: dry-run으로 5문제를 생성해 승인/거절 사유가 로그에 남는다. 정답을 일부러 틀리게 바꾼 문제가 반드시 거절되는 테스트(AI 호출은 목(mock)으로 대체)

**T5-2 AI 스킨 배치**: 템플릿별 스킨 생성과 검증(자리표시자, 숫자 리터럴 검사)
- 완료 기준: 숫자를 추가한 스킨이 거절되는 테스트

**T5-3 자동 격리/은퇴 cron**(03 문서 §5–6) + 격리 시 레이팅 역보정
- 완료 기준: 신고 3건 → 다음 출제에서 제외되는 테스트

## M6. 광고 · PWA · 푸시 (2일)
**T6-1 광고**: `BannerSlot`, `useRewardedAd`(폴백: 5초 대기), `/api/ads/reward` 토큰 검증, 배치 규칙(05 문서 §8.2)
- 완료 기준: 풀이 화면과 레벨 체크 진행 중에는 광고 컴포넌트가 렌더링되지 않는다는 테스트. 보상 일일 한도 테스트

**T6-2 PWA**: manifest, 아이콘, 서비스 워커(정적 자산 캐시, 오프라인 안내), 홈 화면 추가 유도 배너(3번째 방문 시)

**T6-3 웹 푸시**: 구독 저장, `send-push` 함수, 21:00 스트릭 경고, 12:30 오늘의 문제 알림
- 완료 기준: 로컬에서 테스트 푸시 수신

## M7. 관리자 · 지표 · 출시 준비 (2일)
**T7-1 `/admin`**: 격리 문제 목록(복구/폐기 버튼), 생성 작업 로그와 월 누적 토큰/비용, 의심 사용자 목록, KPI 카드(01 문서 §8: DAU, 레벨 체크 완료율, 가입 전환율, D1/D7, 하루 평균 풀이 수, 신고율, 광고 노출/보상)
**T7-2 이벤트 수집**: `events` 기록 유틸 `track(name, props)`과 주요 지점 계측
**T7-3 법적 페이지**: 개인정보처리방침, 이용약관, 광고 고지
**T7-4 출시 점검**: 05 문서 §10 보안 체크리스트 전 항목 자동/수동 확인, Lighthouse 모바일 성능 80+, 접근성 90+
- 완료 기준: 체크리스트 전부 체크, 프로덕션 배포 URL에서 레벨 체크 → 가입 → 오늘의 문제 → 랭킹 E2E 통과
