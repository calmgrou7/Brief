## Phase 1. 기획·검증

### 1. 한 줄 정의

토스 앱 안에서 **거래처와 품목을 고르기만 하면 견적서·거래명세서·청구서·영수증 PDF를 1분 안에 만들어 카톡으로 보내는** 미니앱.

### 2. 왜 앱인토스인가 (1인 사업자 관점)

| 항목 | 일반 앱 (스토어) | **앱인토스 미니앱** |
|---|---|---|
| 설치 장벽 | 앱스토어에서 검색하고 설치해야 한다 | 토스 앱 안에서 바로 실행된다. 프리랜서·사장님 상당수가 이미 토스를 쓴다 |
| 로그인 | 회원가입 화면을 직접 만들어야 한다 | **토스 로그인** 한 번으로 끝난다 |
| 결제 | PG 계약, 정기결제 직접 구현 | **인앱결제 정기결제**가 SDK에 내장되어 있다 (무료 체험·할인 설정 포함) |
| 유입 | 마케팅비를 직접 써야 한다 | 토스 내 노출, 공유 링크, 푸시 같은 플랫폼 기능을 쓸 수 있다 |
| 신뢰 | 신생 앱이라 결제를 망설인다 | "토스 안의 서비스"라서 결제 신뢰도가 높다 |
| 단점 | – | 플랫폼 정책에 묶인다. 수수료가 있다. TDS 디자인 규칙을 따라야 한다 |

### 3. 문제와 해결

| 지금의 불편 | 1분 견적의 해결 |
|---|---|
| 엑셀·한글 양식을 복사하고, 금액·부가세를 손으로 계산하다 틀린다 | 공급가액, 세액, 합계, 한글 금액(일금 ○○원정)을 자동으로 계산한다 |
| 내 사업자 정보, 계좌, 도장을 매번 다시 붙인다 | 한 번 저장하면 모든 문서에 자동으로 들어간다 |
| 견적서를 영수증이나 청구서로 다시 옮겨 적는다 | 원클릭 변환: 견적서 → 거래명세서 → 청구서 → 영수증 |
| PC가 있어야 문서를 만든다 | 폰에서 PDF를 만들어 바로 공유 시트로 카톡에 보낸다 |
| 문서 번호와 이력이 뒤죽박죽이다 | 번호를 자동으로 매기고, 거래처별 이력을 검색할 수 있다 |

### 4. 타깃과 핵심 시나리오

- **주 타깃**: 프리랜서(디자인, 개발, 영상, 사진, 강의), 현장 1인 사장님(인테리어, 청소, 수리, 이사).
- **첫 고객은 나**: 기획자 본인이 실제 견적과 영수증 발행에 매일 쓰고, 불편한 점을 백로그에 바로 넣는다.

| # | 시나리오 | 목표 시간 |
|---|---|---|
| S1 | 토스에서 미니앱 실행 → 토스 로그인 → 내 정보 3개 입력 → 첫 견적서 PDF를 카톡으로 공유 | 3분 |
| S2 | 기존 거래처에게 새 견적서 작성(최근 품목 재사용) | **1분** |
| S3 | 보낸 견적서를 영수증으로 변환해서 재발송 | 15초 |
| S4 | 프리랜서가 3.3% 원천징수를 반영한 청구서 발송 | 1분 |

### 5. 검증 계획 (개발 전 1주)

1. **인터뷰 5명**: 프리랜서와 1인 사장님에게 다음을 묻는다.
   - 지금 견적서를 어떻게 만드는지
   - 한 달에 몇 건 만드는지
   - 무엇이 가장 귀찮은지
   - 월 4,900원을 낼 의향이 있는지
2. **가짜 문 테스트**: 노션이나 간단한 랜딩 페이지에 "토스에서 1분 만에 견적서" 대기자 폼을 만든다. 지인과 커뮤니티 3곳에 올려 대기자 30명을 목표로 한다.
3. **통과 기준**
   - 5명 중 3명 이상이 "월 1회 이상 문서를 만든다"고 답한다.
   - 대기자 30명을 모은다.
   - 미달하면 타깃(예: 현장 사장님만)이나 문서 유형을 좁혀서 다시 검증한다.

### 6. 가격 가설

| | 무료 | **Pro 월 4,900원** | Pro 연 39,000원 (2개월 이상 할인) |
|---|---|---|---|
| 문서 생성 | 월 3건 + **리워드 광고 1회 시청당 +1건** (월 최대 +5건) | 무제한 | 무제한 |
| PDF 워터마크 | "토스 1분 견적으로 작성" 하단 표시 | 제거 | 제거 |
| 로고·도장 | 도장만 | 로고 + 도장 | 동일 |
| 거래처·품목 저장 | 각 10개 | 무제한 | 무제한 |
| 템플릿 | 기본 1종 | 3종 + 브랜드 색 | 동일 |
| 매출 리포트(월별 합계, CSV) | ✕ | ✓ | ✓ |
| 광고 | 리워드 광고만 (사용자가 선택했을 때만) | 없음 | 없음 |

- **가격 근거**: 토스 사용자는 소액 결제 감도가 높다. 그래서 일반 웹 버전 계획(6,900원)보다 낮게 시작한다. 인앱결제 가격은 400원 이상으로만 설정할 수 있다 `[확인]`.
- **무료 체험**: 콘솔의 구독 무료 체험 기능으로 **7일**을 설정한다.
- **수수료 반영**: 인앱결제에는 앱마켓 수수료와 앱인토스 수수료가 붙는다(요율 `[확인]`). 가격은 **최악의 경우 30%가 빠져도 남는 구조**로 잡는다.
  - 서버비는 사용자 1,000명 기준 월 수만 원 수준이다.

### 8. 기술 스택 (결정 사항)

| 영역 | 선택 | 비고 |
|---|---|---|
| 미니앱 | **Vite + React + TypeScript + `@apps-in-toss/web-framework`** (WebView) | SDK 메이저 버전(v2/v3)은 M0에서 최신으로 확정한다. v3에서 API 이름이 바뀌었다 |
| 디자인 | **TDS (Toss Design System) WebView 패키지** | 비게임 WebView 미니앱은 **TDS가 필수이고 검수 기준에 포함**된다 |
| 백엔드 | **Supabase** (Postgres + Edge Functions + Storage) | 로그인 토큰 교환, IAP 웹훅, 데이터 동기화 |
| PDF | `@react-pdf/renderer` + Pretendard 폰트 임베드 (클라이언트에서 생성) | 기기마다 결과가 같다 |
| 파일 내보내기 | SDK 파일 저장 API (v2 `saveBase64Data` / v3 `File.saveBase64`) | 내부적으로 **OS 공유 시트**가 열려서 카톡 전송으로 바로 이어진다 |
| 공유 | SDK 공유 링크 (v2 `getTossShareLink` / v3 `Share.createLink`) + `share` | 미니앱 초대(바이럴)용 |
| 테스트 | Vitest(계산 엔진), 샌드박스 앱 수동 QA 체크리스트 | |

**설계 원칙**
1. 계산과 포맷 로직은 `src/lib/calc/`의 **순수 함수**로만 둔다.
2. SDK 호출은 `src/lib/toss/` 래퍼 한 곳에만 둔다. SDK 버전이 바뀌면 이 폴더만 고친다.
3. 요금제 한도와 가격은 `src/lib/plan.ts` 한 곳에만 둔다.

### 10. 기능 명세

#### 10.1 문서 유형

| 유형 | 번호 예 | 핵심 필드 |
|---|---|---|
| 견적서 | Q-2026-0001 | 유효기간(기본 14일), 납기·조건 |
| 거래명세서 | S-2026-0001 | 거래일, 인수자 서명란 |
| 청구서 | I-2026-0001 | 입금 기한, **입금 계좌**, 3.3% 옵션 |
| 영수증 | R-2026-0001 | 수령일, 결제수단, "위 금액을 정히 영수함" |

- **변환**: 품목, 거래처, 세금 설정을 복사하고 새 번호를 발급한다. `source_doc_id`로 원본과 연결한다.
- **발행 시 스냅샷**: 공급자와 거래처 정보를 발행 시점 값으로 얼려서 저장한다. 나중에 설정을 바꿔도 과거 문서는 바뀌지 않는다.

#### 10.2 계산 명세 (`src/lib/calc`, 순수 함수)

1. **줄 금액** = `Math.round(qty × unitPrice)`. 수량은 소수 둘째 자리까지 허용한다.
2. `base = Σ줄금액 − discount`. 할인이 소계보다 크면 에러다.
3. **부가세 별도(`exclusive`)**: `supply = base`, `tax = floor(supply × 0.1)`, `total = supply + tax`
4. **부가세 포함(`inclusive`)**: `total = base`, `supply = floor(total × 10 / 11)`, `tax = total − supply`
5. **면세·간이(`exempt`)**: `tax = 0`
6. 세액은 **문서 합계 기준으로 한 번만** 계산한다. 줄마다 계산해서 더하지 않는다.
7. **3.3%**: 소득세 `floor10(total × 0.03)`, 지방소득세 `floor10(소득세 × 0.1)`, 실지급액 = `total − 둘의 합`
8. **한글 금액**: "일금 일백이십삼만사천오백원정" 형식. 십·백·천 앞의 "일"을 생략하지 않는다.
9. **사업자번호 검증**
   - 가중치 `[1,3,7,1,3,7,1,3,5]`로 `Σ d[i] × w[i]`를 구하고, 여기에 `floor(d[8] × 5 / 10)`을 더한다.
   - `(10 − sum % 10) % 10 === d[9]`이면 유효하다.
   - 실패해도 막지 않고 경고만 한다.
10. **문서 번호**: `{Q|S|I|R}-{YYYY}-{0001}`. 사용자별·유형별·연도별로 순번을 매긴다.

#### 10.3 테스트 벡터 (Vitest, 기대값 고정 — 사전 계산으로 검증 완료)

| # | 입력 | 기대값 |
|---|---|---|
| C1 | 별도, [1×500,000, 2×50,000] | 공급 600,000 / 세액 60,000 / 합계 660,000 |
| C2 | 포함, [1×110,000] | 100,000 / 10,000 / 110,000 |
| C3 | 포함, [1×100,000] | **90,909 / 9,091** / 100,000 |
| C4 | C1 + 할인 50,000 | 550,000 / 55,000 / 605,000 |
| C5 | 별도, [3×33,333] | 99,999 / 9,999 / 109,998 |

#### 10.4 수익화 구현

**A. 인앱결제 정기결제 (구독)**
- SDK 구독 함수를 쓴다(공지 기준 `createSubscriptionPurchaseOrder`, `getSubscriptionInfo`, v3 이름은 `[확인]`).
- **권한(entitlement)의 기준은 서버**다. 클라이언트에서 구매에 성공해도 바로 Pro로 바꾸지 않는다. 서버에서 주문을 검증하거나 웹훅을 받은 뒤 `subscriptions` 테이블을 갱신하고, 클라이언트는 `entitlement`를 다시 조회한다.
- **웹훅**(`iap-webhook`)으로 받는 이벤트: 구독 시작, 갱신, 결제 실패, 해지, 환불.
  - 이벤트마다 `status`와 `current_period_end`를 갱신한다.
  - 같은 이벤트가 두 번 와도 결과가 같도록 처리한다(멱등, `order_id` 유니크).
- **원격 플래그**: `remote_config.paywall_enabled`. 출시 직후 2주는 `false`로 두고, 이때는 무료 한도도 넉넉하게(월 10건) 준다. 플래그를 켜면 §6 요금제를 적용한다.
- **복원**: 앱을 실행할 때마다 `entitlement`를 조회해서 기기를 바꾸거나 재설치해도 구독이 유지되게 한다.

**B. 리워드 광고 (무료 사용자)**
- 무료 한도에 도달하면 바텀시트를 띄운다: `[광고 보고 1건 더 만들기]` `[Pro 7일 무료 체험]`.
- 광고 시청 완료 콜백을 받으면 서버에 `ad_rewards`를 기록하고 보너스를 1건 늘린다. 클라이언트 단독으로 보너스를 늘리지 않는다.
- 배너나 전면광고는 쓰지 않는다. 문서 도구에서 사용자 경험을 해치기 때문이다.

**C. 워터마크 (바이럴)**
- 무료 PDF 하단에 "토스 1분 견적으로 작성 · 토스에서 '1분 견적' 검색"을 넣는다. 받는 사람도 대부분 사업자라서 홍보가 된다.
- 문구에 외부 링크를 넣어도 되는지는 검수 정책을 `[확인]`한다.

#### 10.5 화면·UX (TDS 컴포넌트 사용)

1. **온보딩** (3단계 이내)
   - 토스 로그인을 한다.
   - 상호, 대표자, 연락처를 입력한다. 사업자번호는 선택이다.
   - "프리랜서 / 일반과세 / 간이·면세"를 고르면 기본 세금 모드가 정해진다.
   - 바로 첫 견적서 작성으로 넘어간다.
2. **홈**
   - 최근 문서 목록과 상태(작성 중 / 발송 / 입금완료)를 보여준다.
   - 이번 달 사용량을 "무료 2/3건"처럼 표시한다.
   - 하단에 `[+ 새 문서]` 큰 버튼을 둔다.
3. **작성** (단일 화면): 유형 탭 → 거래처 칩 → 품목(자동완성, 최근 칩) → 세금 모드 → 메모. 하단에 고정 바 `합계 ₩660,000 · [미리보기]`를 둔다. 입력하는 즉시 자동 저장한다.
4. **미리보기**: A4 비율로 보여준다. 버튼은 `[PDF 보내기]`(파일 저장 API → 공유 시트), `[유형 변환]`, `[복제]`.
5. **페이월**
   - 혜택 3줄과 월/연 선택을 둔다. 연을 기본으로 선택해 두고 "2개월 무료"를 강조한다.
   - 버튼 문구는 `[7일 무료로 시작하기]`다.
   - 해지 방법과 결제 주기를 같은 화면에 고지한다.
6. **설정**: 내 사업자 정보, 계좌, 로고·도장 이미지, 기본 유효기간, 구독 관리(해지는 토스의 구독 관리로 안내 `[확인]`).

### 11. 법·세무·플랫폼 주의사항

- 이 앱의 영수증과 거래명세서는 **세법상 적격증빙(세금계산서, 카드전표, 현금영수증)이 아니다.** 영수증 화면에 안내 툴팁을 둔다.
- 전자세금계산서 발행은 범위 밖이다. 대신 홈택스 안내를 둔다.
- 3.3%는 인적용역 사업소득 기준이다. 세무사 확인을 권하는 고지를 둔다.
- 거래처 연락처는 개인정보다. 개인정보처리방침에 수집 항목, 목적, 보관 기간을 명시한다.
- 정기결제 고지: 금액, 주기, 무료 체험 종료일, 해지 방법을 결제 전에 보여준다.
- **디지털 구독은 인앱결제로만 판매한다.** 외부 결제 링크로 유도하지 않는다. 플랫폼 정책 위반이 될 수 있다.
- 광고 정책을 위반하면 30일 정지나 영구 정지가 될 수 있다. 테스트 ID 사용을 지키고, 사용자가 광고를 실수로 누르게 유도하는 배치를 하지 않는다.

### 12. 검수 대비 체크리스트

앱인토스 검수는 운영, 기능, 디자인, 보안 4단계이고, 검토 기간은 **영업일 기준 최대 3일**이다. 승인 후 '출시하기'를 누르면 **전체 사용자에게 즉시 공개**된다.

- [ ] 비게임 검수 가이드를 최신본으로 다시 읽는다 `[확인]`.
- [ ] **디자인**: TDS 컴포넌트를 사용하고, 다크모드를 지원하고, 내비게이션 바 규칙을 따른다.
- [ ] **기능**
  - 샌드박스에서 S1~S4가 전부 동작한다.
  - 로그인을 취소하거나 결제를 취소했을 때 앱이 정상으로 돌아온다.
  - 네트워크 오류 시 안내가 나온다.
- [ ] **결제**: 구독 구매, 갱신, 해지, 복원 흐름과 테스트 결제 내역 캡처.
- [ ] **광고**: 실제 광고 ID로 바꿨는지 확인한다. 리워드 지급은 서버가 확인한 뒤에 한다.
- [ ] **보안**: 비밀키가 클라이언트 번들에 없는지 확인한다(`grep`으로 점검). RLS가 켜져 있는지 확인한다.
- [ ] **운영**: 개인정보처리방침·약관 URL, 고객 문의 채널(이메일 또는 오픈채팅), 앱 소개 문구와 스크린샷.
- [ ] 반려되면 사유를 `docs/review-log.md`에 기록하고, 고친 뒤 다시 제출한다.

| 첫 문서 생성까지 걸린 시간(중앙값) | 3분 이하 | 2분 이하 |

| 체험 → 유료 전환율 | 40% | 50% |
| 월 해지율 | – | 5% 이하 |
| MRR | 50만 원 | 300만 원 |

### 18. 수익 시뮬레이션 (참고)

- 가정: 월간 활성 사용자 3,000명 × 구독 전환 5% = 구독자 150명
- 구독자 구성: 월 구독 60%, 연 구독 40% (연 39,000원 ÷ 12 = 월 약 3,250원)
- 월 구독 매출: 90명 × 4,900원 ≈ 441,000원
- 연 구독 매출(월 환산): 60명 × 3,250원 ≈ 195,000원
- 합계: 월 약 64만 원 + 리워드 광고 수익
- 수수료는 별도다. 공식 요율을 확인한 뒤 갱신한다.
- 매출을 늘리는 순서
  1. 연 구독 비중을 늘린다.
  2. Biz 플랜을 추가한다.
  3. 토스 밖 웹 버전을 만든다. 이전 기획서 `quote-app/PLAN.md`를 재사용한다.
