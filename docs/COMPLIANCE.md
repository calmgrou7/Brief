# 규제 · 스토어 심사 체크리스트

> 이 문서와 앱 안의 동의서·약관·개인정보처리방침 문구는 **초안**입니다. 출시 전 변호사 또는 개인정보 전문가 검토를 받으세요.

## 사업 구조 (가장 먼저 결정)
- [ ] 상담 주체: 본인이 설계사·GA 소속이면 직접 상담. 아니라면 제휴 설계사·GA에 연결하는 구조
- [ ] 제3자 제공: 리드를 넘긴다면 `NEXT_PUBLIC_THIRD_PARTY_RECIPIENTS`에 **받는 곳의 실명**을 적어야 제3자 제공 동의 항목이 나타남
- [ ] 보험금 청구: **안내만** 하고 대행·손해사정은 하지 않음 (약관 제2조에 명시됨). 유료 청구 대행은 자격 문제가 생길 수 있음
- [ ] 상품 권유: AI와 화면 문구 모두 특정 상품 권유 없이 정보 제공에 한정 (시스템 프롬프트에 반영됨)

## 개인정보 (구현 현황)
| 요구사항 | 구현 |
|---|---|
| 필수·선택 동의 분리, 전체 동의 | `LeadForm` + `consent.ts` |
| 민감정보(건강 관련 응답) 별도 동의 | 점검 결과를 연결할 때만 필수로 노출 |
| 동의 이력 보존 (항목·버전·시각·IP) | `consents` 테이블, 리드를 삭제해도 보존 |
| 본인 확인 | 문자 인증 (서명 토큰 방식) |
| 대화 내 개인정보 보호 | 전화번호·주민번호 패턴 마스킹 후 저장·전송 |
| 삭제·수신 거부 요청 | `/privacy#request` → 대시보드에 처리 대기 표시 (10일 내 처리) |
| 보유기간 경과 자동 파기 | `purge_expired()` 함수 → Supabase cron으로 매일 실행 |
| DB 직접 접근 차단 | 모든 테이블 RLS 활성화 + 정책 없음 (서버 service_role만 접근) |
