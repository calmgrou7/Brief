# DOIT 앱 기획서 v0.1 — 회원가입 + 유료 구독 · Google Play 출시

> 작성일: 2026-11-08 · 상태: **v0.2 — 주요 결정 확정, 개발 착수**
> 표시 규칙: ✅ 확정 · 💡 제안(결정 필요) · ⚠️ 정책/법규 — 출시 전 공식 문서로 재확인

## 1. 한 줄 정의

**DOIT** — 큰 목표를 10~30분짜리 할 일로 쪼개 주고, 매일 "오늘의 DO 3"만 실행하게 만드는 실행 관리 앱.
수익 모델: **무료 + 월/연 구독(프리미엄)**. 1차 출시는 **Android(Google Play)**.

## 2. 무료 vs 프리미엄 💡

| 기능 | 무료 | 프리미엄 |
| --- | --- | --- |
| 목표 등록 | 3개 | 무제한 |
| AI 목표 쪼개기 | 월 3회 | 무제한(공정사용 한도) |
| 오늘의 DO 3 · 체크 · 연속기록 | ✔ | ✔ |
| 리마인드 알림 | 하루 1회 고정 | 시간·횟수 자유 설정 |
| 주간 실행 리포트 | 요약만 | 상세(시간대·실행률 추이) |
| 반복 업무 템플릿 | ✖ | ✔ |
| 홈 화면 위젯 | ✖ | ✔ |

**가격(안)**: 월 4,900원 / 연 39,000원(약 34% 할인) / **7일 무료체험**
**사전등록자 혜택**: 랜딩페이지에 "3개월 무료"로 안내됨 → Play 구독 **프로모션 코드** 또는 사전등록자 전용 오퍼로 구현 (방식 결정 필요)

> 핵심 원칙: 무료만으로도 "쪼개기 → 실행 → 기록"의 경험은 끝까지 가능해야 함. 유료는 "더 많이·더 편하게".

## 3. 사용자 흐름

```
앱 설치 → 온보딩 3장(가치 설명) → 회원가입(구글 / 이메일)
→ 첫 목표 입력 → AI가 쪼개기 → 오늘의 DO 3 선택 → 체크
→ (한도 도달 또는 리포트 진입 시) 페이월 → 7일 무료체험 시작
```

- 첫 목표 쪼개기는 **가입 직후 바로** 체험하게 해서 가치를 먼저 느끼게 함
- 페이월은 "한도 도달" 시점에 노출 (앱 시작 시 강제 노출 ✖)

## 4. 회원가입 · 계정

| 항목 | 내용 |
| --- | --- |

| 연령 | 💡 **만 14세 이상만 가입** (14세 미만은 법정대리인 동의 절차가 필요해 MVP에서 제외) |

## 5. 결제 · 구독 (가장 중요)

### 5-1. 정책 ⚠️
- 앱 안에서 디지털 기능(프리미엄)을 판매하면 **Google Play 결제 시스템 사용이 원칙**. 카드 결제(PG)·계좌이체로 앱 내 판매 ✖
- 한국 사용자 대상으로는 **제3자 결제(대체 결제) 병행**이 허용되지만, 수수료 차이가 작고(약 4%p 인하) 구현·정산 부담이 커서 **MVP는 Play 결제만 사용** 권장
- 수수료: **자동갱신 구독은 15%**
- 구독 관련 필수 고지: 가격·갱신 주기·무료체험 종료 후 자동 결제·해지 방법을 결제 전 화면에 명확히 표시

### 5-2. 구현 구조 💡
```
[앱] ──구매──▶ Google Play Billing
  │                  │
  │            (실시간 알림 RTDN)
  ▼                  ▼
RevenueCat SDK ──▶ RevenueCat 서버 ──웹훅──▶ Supabase (구독 상태 저장)
  │                                              │
  └──── "premium" 권한 확인 ◀────────────────────┘
```
- **RevenueCat 사용 이유**: 영수증 검증·갱신·해지·환불·유예기간 처리를 대신 해 줌 → 1인 개발에서 결제 버그 리스크를 크게 줄임. 월 매출 $2,500까지 무료, 이후 매출의 1%
- 직접 구현 시 필요한 것: Play Developer API로 서버 검증, Pub/Sub 실시간 알림, **구매 후 3일 내 승인(acknowledge)** — 미승인 시 자동 환불
- 처리해야 할 상태: 체험중 / 활성 / 유예기간(결제 실패) / 계정 보류 / 해지 예약 / 만료 / 환불

### 5-3. Play Console 상품 설정
- 구독 상품 1개 `doit_premium` 안에 **기본 요금제 2개**: `monthly`, `yearly`
- 오퍼: 신규 가입자 7일 무료체험 (1인 1회)

## 6. 기술 스택 💡

| 영역 | 선택 | 이유 |
| --- | --- | --- |
| 앱 | **React Native (Expo)** | 한 코드로 Android → 추후 iOS. Claude Code로 개발하기 쉬움. EAS로 빌드·스토어 제출 자동화 |
| 백엔드 · DB · 인증 | **Supabase** (이미 연결된 계정 사용) | 로그인·DB·서버함수 한 곳에서. 무료로 시작 |
| 결제 | **RevenueCat** + Google Play Billing | 위 5-2 참고 |
| AI 쪼개기 | **Claude API** (Supabase Edge Function에서 호출) | API 키를 앱에 넣지 않고 서버에서만 사용. 비용 효율 모델 우선 |
| 알림 | Expo Notifications(로컬) → 추후 FCM | MVP는 로컬 알림으로 충분 |
| 분석 | PostHog 또는 Firebase Analytics | 가입→첫 쪼개기→체험→결제 전환율 추적 |
| 배포 | EAS Build + EAS Submit, GitHub Actions | 커밋하면 테스트 트랙까지 자동 업로드 |

### DB 테이블(초안)
- `profiles` — 사용자, 닉네임, 가입일, 마케팅 동의
- `goals` — 목표, 마감일, 상태
- `tasks` — 목표별 할 일, 예상 시간, 순서, 완료일
- `daily_focus` — 날짜별 DO 3 선택
- `entitlements` — 구독 상태(웹훅으로만 갱신), 만료일
- `ai_usage` — 월별 AI 사용 횟수(무료 한도 체크)

## 7. Google Play 출시 체크리스트 ⚠️

### 개발자 계정
- [ ] 등록비 **$25** (1회)
- [ ] 💡 **계정 유형 결정**
  - **조직(사업자) 계정** 권장: 사업자 명의로 표시, **D-U-N-S 번호** 필요(무료 발급, 수일~수주 소요)
  - **개인 계정**: 2023-11 이후 만든 개인 계정은 프로덕션 출시 전 **테스터 12명 이상이 14일 연속 참여하는 비공개 테스트**를 반드시 통과해야 함
- [ ] 판매자 결제 프로필(사업자 정보·정산 계좌) 등록 — 없으면 유료 상품 생성 불가
- [ ] 신원·사업자 확인 완료

### 스토어 등록 자료
- [ ] 앱 아이콘 512×512, 그래픽 이미지 1024×500, 스크린샷 최소 2장
- [ ] 간단한 설명(80자), 자세한 설명(4,000자)
- [ ] **개인정보처리방침 URL** (필수) → 홈페이지에 페이지 추가
- [ ] **계정 삭제 요청 URL** (필수) → 홈페이지에 페이지 추가
- [ ] 데이터 보안(Data safety) 설문: 수집 항목(이메일, 이름, 앱 활동, 구매 내역) · 전송 암호화 · 삭제 요청 가능 여부
- [ ] 콘텐츠 등급 설문, 타겟 연령(만 14세 이상 → 13세 이상으로 설정), 광고 포함 여부(없음)
- [ ] 심사용 테스트 계정 정보 제공 (로그인 필요한 앱은 필수)
- [ ] **최신 타깃 API 레벨** 충족 (Expo SDK 최신 버전 사용 시 대부분 자동 충족, 제출 시점에 재확인)

### 국내 법규 ⚠️ (세무사·법무 확인 권장)
- [ ] 사업자등록 업종에 소프트웨어/앱 서비스 추가 여부 확인
- [ ] **통신판매업 신고** 필요 여부 확인
- [ ] 이용약관 · 개인정보처리방침 작성 (구독·환불·해지 조항 포함)
- [ ] 무료체험 → 유료 전환, 가격 인상 시 사전 고지·동의 (전자상거래법)
