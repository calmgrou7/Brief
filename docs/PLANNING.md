# 단체 회원관리 플랫폼 기획안 (초안)

> 대상: 협회·연합회 등 단체의 **사무장님·임원진**
> 형태: 단체 단위로 구독하는 웹 서비스(SaaS)
> 작성일: 2026-11-11

---

## 1. 한 줄 정의

"사무장님이 엑셀, 카톡, 종이 명함으로 따로 관리하던 회원 정보·연혁·행사·매뉴얼을 **한 곳에 모으고**, 코드를 받은 임원진만 들어와서 보는 단체 전용 업무 공간."

## 2. 왜 사무장님에게 좋은가 (팔리는 포인트)

| 지금의 불편 | 플랫폼에서 해결 |
|---|---|
| 회원 명단이 엑셀·단톡방·명함첩에 흩어져 있음 | 회원 카드 1장에 얼굴 사진·명함·연락처·메일·업종이 모여 있음 |
| 사무장이 바뀌면 업무 노하우가 사라짐 | 매뉴얼 메뉴에 업무 절차가 남아서 인수인계가 됨 |
| "작년 행사 언제였지?" 하고 매번 찾음 | 연혁 타임라인과 올해 행사 캘린더 |
| 공지 메일을 한 명씩 보냄 | 그룹을 골라 한 번에 메일 발송 |
| 임원 임기가 끝나도 자료 접근 권한이 남음 | 코드 유효기간 1년, 만료되면 자동으로 접근 차단 |

## 3. 사용자와 권한

| 역할 | 로그인 | 할 수 있는 일 |
|---|---|---|
| **플랫폼 운영자** (나) | O | 단체 등록, 구독 관리, 전체 지원 |
| **사무장** (단체 관리자) | O (코드) | 회원 등록·수정, 코드 발급·연장, 행사·연혁·매뉴얼 작성, 메일 발송 |
| **임원진** | O (코드) | 열람, 일부 작성(행사 후기·매뉴얼 등은 단체가 정함) |
| **일반 회원** | X | 로그인 불가. 정보는 사무장이 관리하고, 동의한 경우에만 홍보 페이지에 노출 |

### 접근 코드 방식
1. 사무장이 임원 이름·이메일을 넣고 **초대 코드**를 발급 (예: `KAB-7F3K-92QD`)
2. 임원은 코드를 입력하고 이메일 인증 후 첫 로그인 → 계정 생성
3. 계정 유효기간 = 발급일로부터 **1년** (`expires_at` 필드)
4. **만료 30일 전·7일 전 자동 알림 메일**을 사무장과 본인에게 발송
5. 사무장이 버튼 하나로 1년 연장하거나, 임기가 끝난 사람은 즉시 해지
6. 코드는 1회용이며, 로그인 이후에는 이메일 + 비밀번호(또는 매직링크)로 접속

> 코드만으로 로그인하게 만들면 코드가 단톡방에 돌아다닐 때 막을 방법이 없습니다. 그래서 **코드는 가입할 때 한 번만 쓰고, 이후에는 본인 이메일로 로그인**하게 하는 것을 권장합니다.

## 4. 기능 범위

### MVP (1차, 약 4~6주)
- **회원 관리**: 회원 카드(얼굴 사진, 명함 앞뒷면, 이름, 상호, 직책, 연락처, 이메일, 업종, 가입일, 회비 납부 여부, 메모), 검색·필터, 엑셀 가져오기·내보내기
- **접근 코드**: 발급, 1년 만료, 연장, 해지
- **올해 행사**: 캘린더와 목록, 행사별 사진과 참석자
- **연혁**: 연도별 타임라인 (행사가 끝나면 연혁에 자동으로 추가)
- **매뉴얼**: 업무 매뉴얼 문서 (카테고리, 첨부파일)
- **메일 발송**: 전체 회원, 임원진, 업종별 등 그룹을 골라 발송

### 2차 (파일럿 피드백 이후)
- **회원 홍보 페이지**: 동의한 회원만 공개되는 "회원사 소개" 페이지 (명함·소개글·지도 링크), 단체 홈페이지에 붙일 수 있는 링크
- **명함 사진 자동 입력**: 명함 사진을 올리면 AI가 이름·연락처·이메일·상호를 읽어서 회원 카드를 채움
- **매뉴얼 AI 검색**: "회비 미납자 처리 어떻게 해?"라고 물으면 매뉴얼에서 찾아서 답해 줌
- **카카오 알림톡** 연동 (메일보다 확인율이 높음)
- **구독 자동결제**

## 5. 1인 운영에 맞춘 자동화 설계

혼자 운영해도 손이 덜 가도록 처음부터 자동화를 넣어 두는 것이 핵심입니다.

| 자동화 | 효과 |
|---|---|
| 명함 사진 → AI 자동 입력 | 사무장님 입력 시간 절감. 데모할 때 가장 반응이 좋은 기능 |
| 코드 만료 사전 알림 + 원클릭 연장 | 운영자가 갱신을 챙길 필요가 없음 |
| 행사 종료 → 연혁 자동 등록 | 연혁이 저절로 쌓임 |
| 구독 결제 실패 → 자동 안내 메일 → 유예 기간 후 읽기 전용 전환 | 미수금 관리 자동화 |
| 단체 신규 가입 → 템플릿 자동 세팅 (기본 매뉴얼 목차, 회원 필드) | 온보딩을 사무장님이 직접 함 |
| 엑셀 회원명단 업로드 → 자동 정리 | 첫 도입 시 이전 장벽 제거 |

## 6. 기술 구성 (저렴하게)

| 영역 | 선택 | 이유 |
|---|---|---|
| 프론트·서버 | Next.js | 웹 + 모바일 브라우저 대응, 개발 생태계가 큼 |
| DB·로그인·파일 | **Supabase** (Postgres + Auth + Storage) | 로그인, 사진 저장, 권한(RLS)을 한 번에 해결. 단체별 데이터 분리가 쉬움 |
| 호스팅 | Render 또는 Vercel | 초기에는 월 0~2만 원대 |
| 메일 | Resend 등 메일 API | 초기 무료 구간이 있음 |
| 명함 인식·AI 검색 | Claude API | 사용한 만큼만 과금되고, 명함 1장당 수 원 수준 |
| 결제 | 토스페이먼츠 / 포트원 정기결제 | 국내 카드 자동결제 |

**데이터 구조 (핵심 테이블)**
```
organizations   단체 (구독 상태, 요금제)
members         회원 카드 (단체 소속, 사진/명함 경로, 홍보 공개 동의 여부)
staff_accounts  로그인 계정 (사무장/임원, role, expires_at)
invite_codes    초대 코드 (1회용, 발급자, 사용 여부)
events          행사 (날짜, 장소, 사진, 연혁 반영 여부)
history         연혁 항목
manuals         매뉴얼 문서
mail_campaigns  메일 발송 이력
```
모든 테이블에 `organization_id`를 두고, Supabase RLS로 **다른 단체 데이터는 DB 단에서부터 보이지 않게** 막습니다. 멀티테넌트 구조라 단체가 늘어나도 서버 하나로 운영할 수 있습니다.

### 월 운영비 예상
- 단체 1~10곳: **월 3~5만 원** (Supabase Pro 약 $25 + 호스팅 + 도메인)
- 단체 50곳 이상: 사진 저장 용량과 메일 발송량에 따라 월 10만 원 안팎

## 7. 구독 요금 (안)

| 요금제 | 월 요금 | 대상 |
|---|---|---|
| 베이직 | 19,000원 | 회원 100명, 로그인 계정 10개 |
| 스탠다드 | 39,000원 | 회원 500명, 계정 30개, 명함 AI 인식, 홍보 페이지 |
| 연간 결제 | 2개월 할인 | 단체 회계연도에 맞춰 결제하기 편함 |

> 단체는 보통 **연 단위 예산**으로 움직이므로, 월 구독보다 **연간 결제 + 세금계산서 발행**이 더 잘 팔릴 가능성이 높습니다. 코드 유효기간 1년과도 주기가 맞습니다.

## 8. 꼭 챙겨야 할 것: 개인정보

얼굴 사진, 명함, 연락처, 이메일은 모두 **개인정보**입니다.
- 회원 등록 시 **개인정보 수집·이용 동의**를 받아야 함 (단체가 받고, 플랫폼은 처리를 위탁받는 구조)
- **홍보 페이지 공개는 별도 동의**를 받아야 함 (체크박스를 분리)
- 개인정보처리방침과 위탁계약 문구를 이용약관에 포함
- 사진 파일은 비공개 저장소에 두고, 서명된 URL로만 열람
- 접근 기록(누가 언제 회원 정보를 봤는지) 로그 저장
- 만료·해지된 계정은 즉시 접근 차단 (1년 코드 정책이 여기서도 도움이 됨)

## 9. 진행 순서

| 단계 | 기간 | 할 일 | 결과물 |
|---|---|---|---|
| 0. 검증 | 1주 | 사무장님 2~3명 인터뷰: 지금 쓰는 엑셀 양식, 가장 귀찮은 업무, 얼마면 쓰겠는지 | 기능 우선순위 확정 |
| 1. 화면 설계 | 1주 | 핵심 화면 6개 와이어프레임 (로그인, 회원 목록, 회원 카드, 행사, 연혁, 매뉴얼) | 클릭 가능한 시안 |
| 2. MVP 개발 | 4~6주 | 4장의 MVP 범위 | 실제 쓸 수 있는 서비스 |
| 3. 파일럿 | 1~2개월 | 아는 단체 1곳에 **무료로** 실사용. 회원 명단 이전을 직접 도와주기 | 후기, 사례, 개선 목록 |
| 4. 유료화 | 이후 | 결제 연동, 소개 페이지, 사무장 모임과 연합회 단위로 영업 | 첫 유료 단체 |

## 10. 결정이 필요한 질문

1. 첫 파일럿 단체는 어디인가? (그 단체의 실제 회원 명단 양식이 기본 필드가 됨)
2. 회원 홍보 페이지는 **외부 공개**인가, **임원진 내부 열람**인가?
3. 임원진도 회원 정보를 **수정**할 수 있는가, **열람만** 하는가?
4. 메일 외에 **카카오 알림톡**이 1차에 필요한가?
5. 단체 하나만 쓰는 맞춤 제작인가, 여러 단체에 판매하는 구독형인가? (구독형이면 처음부터 멀티테넌트로 설계)
