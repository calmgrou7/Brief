# AEGIS TRADE AI — 업비트 현물 자동매매 프로그램 PRD 및 개발 지시서

- 버전: 1.0
- 작성 기준일: 2026-10-31 (Asia/Seoul)
- 상태: **설계 초안 / 구현 전 / 실제 계정 미연동**
- 대상: 단일 사용자, 개인 자기자금, 업비트 KRW 현물 거래
- 기본 운영 모드: `PAPER` (실거래 금지)
- 지향점: 수익 보장형 AI가 아니라 **손실을 통제하며 전략을 검증하는 24시간 자동매매 운영 시스템**

> 이 문서는 개발 명세입니다. 투자 수익을 보장하지 않으며, 실거래 전에 거래소 약관, 계정 자격, API 사용 조건, 세금과 수수료를 확인해야 합니다.

## 1. 제품 목표 및 범위

### 1.1 목표
1. 업비트 KRW-BTC의 시세·거래량·캔들 데이터를 지속 수집한다.
2. 세 가지 연구용 전략을 동일한 가정에서 백테스트하고 우수 후보를 선정한다.
3. 선정된 전략의 확정 버전만 24시간 모의주문 엔진으로 실행한다.
4. 위험관리 엔진을 주문 실행과 별도로 구현하여 AI도 우회할 수 없게 한다.
5. 모든 주문 신호, 거절 사유, 가상 체결, PnL, API 오류를 기록한다.
6. 모바일 대시보드에서 상태·잔고·성과·알림·긴급 정지를 관리한다.
7. 향후 별도 승인과 검수 후 실거래 모드를 추가할 수 있는 구조를 구축한다.

### 1.2 MVP 범위
- **포함**: KRW-BTC 1종, 4시간봉 신호, 가격·거래량 실시간 수신, 기술지표, 3가지 백테스트, 페이퍼 트레이딩, 위험관리, 모바일 웹 관리자, 일간 요약, 비상중지, 감사로그.
- **제외**: 선물·레버리지·공매도, 알트코인 다종목 동시매매, 타인 자금 운용, 리딩 판매, 고빈도 거래, AI 임의 전략 변경, 출금 자동화, 무승인 실거래, 손실 만회용 배팅 증가.
- **원칙**: 실거래 실행코드는 초기 MVP에서 비활성화(컴파일/환경변수/권한 3중 차단)한다.

## 2. 시스템 설계

```
업비트 공개 API (REST / WebSocket)
       |
       v
[Market Data Ingest] --> [데이터 품질/저장] --> [지표 계산]
                                                |
                                       +--------+---------+
                                       v                  v
                                 [전략 연구/AI]       [고정 전략 엔진]
                                 [백테스트]               |
                                       |                  v
                                 [승인된 전략] ------> [Risk Gate]
                                                         |
                                                 +-------+-------+
                                                 v               v
                                            [Paper Broker]   [Live Broker]
                                            기본 활성화       기본 비활성화
                                                 |               |
                                                 +-------+-------+
                                                         v
                                            [체결/잔고/감사로그]
                                                         |
                                            [대시보드/일간 리포트/경보]
```

- Strategy Engine은 `BUY`, `SELL`, `HOLD` 제안만 발행하며 실제 주문 API 자격증명에 접근할 수 없다.
- Risk Gate는 수량, 손절, 총 노출, 체결 가능성, 중복 여부, 데이터 최신성, 운영 모드를 검사하고 거절할 수 있다.
- Broker Adapter는 `PaperBroker` / `UpbitLiveBroker` 인터페이스로 분리한다. 두 모드 모두 동일한 위험관리 검사를 통과한다.
- AI 모듈은 리서치·자연어 설명·전략 비교·이상 탐지·보고서에 사용한다. AI의 자유형 텍스트를 주문 API에 직접 연결하지 않는다.
- 전략 변경은 **연구 → 백테스트 → 워크포워드 → 모의매매 → 사용자 승인 → 버전 고정** 단계로만 반영한다.

## 4. 매매 전략 후보 — 처음부터 한 개만 실가동

공통 조건: `KRW-BTC`, 확정된 4시간봉만 신호 사용, 현물 롱 전용, 신규 매수 시 위험관리 통과 필수, 매매 수수료와 슬리피지 반영.

### 전략 A — 추세 추종 (우선 연구 후보)
- 진입 후보: 종가 > EMA200, EMA20 > EMA50, RSI가 중립 구간에서 상승 확인, 거래량/변동성 필터 통과.
- 청산 후보: ATR 기반 초기 손절, 추적손절, 추세 이탈. 계수와 지표 값은 **연구 변수**이며 수익성 확정 수치 아님.
- 장점: 추세가 명확할 때 설명 가능. 단점: 횡보장에서 잦은 손절.

### 전략 B — 횡보 평균회귀
- 진입 후보: 장기 추세 부재, 볼린저 하단 근접, RSI 과매도 후 회복.
- 청산 후보: 밴드 중앙 도달, 손절/시간 제한.
- 장점: 비추세 구간 연구. 단점: 급락장에서 계속 하락할 수 있음.

### 전략 C — 변동성 돌파
- 진입 후보: 과거 N개 캔들 범위 돌파 + 거래량 확인 + 과열 필터.
- 청산 후보: ATR 추적손절 및 시간 제한.
- 장점: 강한 가격 움직임 대응. 단점: 가짜 돌파·슬리피지.

**평가 기준**: 단순 승률이 아닌, 거래비용 차감 순손익, 최대낙폭(MDD), Profit Factor, 손익비, 거래 횟수, 변동성, 매수 후 보유(Buy & Hold) 비교, 시기별 견고성.

## 5. 초기 위험관리 설정 (검증용 기본값)

| 설정 | 초기값 | 적용 방식 |
|---|---:|---|
| 시작 자산 | 모의잔고 1,000,000원 | 실거래 입금 아님 |
| 주문 대상 | KRW-BTC만 | 그 외 주문 거절 |
| 레버리지 | 0배(차입 없음) | 현물만 |
| 1회 거래 허용 손실 | 총 평가자산의 0.5% | 예정 손절폭과 수량으로 산출 |
| 1회 최대 매수금액 | 총 평가자산의 10% | 위 0.5% 한도와 함께 더 작은 값 적용 |
| 총 코인 노출 | 평가자산의 20% | 최초 1종목만 |
| 일일 손실 한도 | 당일 시작 순자산 대비 -2% | 신규 매수 중단, 사용자 경고 |
| 전략 전체 낙폭 | 최근 최고 순자산 대비 -8% | 신규 매수 중단, 수동 재승인 필요 |
| 연속 손실 | 3회 | 신규 매수 일시 중지 |
| 손실 시 물타기/마틴게일 | 불허 | 예외 없음 |
| 모의검증 | 최소 30일 + 충분한 거래 표본 | 부족하면 연장 |
| 거래 시간 | 24시간 감시, **완료된 4시간봉에서만** 신규 신호 확정 | 미완성봉 진입 금지 |

- 위험예산을 초과하는 매수 수량은 자동으로 축소한다. 최소 주문금액 5,000원 미만이면 주문하지 않는다.
- `risk_budget = equity * 0.005`; `quantity_by_risk = risk_budget / max(entry - stop, minimum_price_step)`; 최종 수량은 `min(quantity_by_risk, max_order_krw/entry, available_krw/entry)`.
- 손절가는 가격 괴리와 급락에 의해 **보장된 체결 가격이 아니다**. 서버 장애·API 장애·비정상 유동성 시 손실 제한을 초과할 수 있다.
- 잔고·체결·미체결 상태가 불일치하면 신규 매수를 금지한다. 매도도 대상 잔고를 재확인한다.
- 거래 비용의 실제 적용 수수료, 매수·매도 호가차, 슬리피지를 별도 구성값으로 관리하고 백테스트에도 반영한다.

## 6. API 연동 관련 실무 요구사항

공식 문서 확인일 기준:
- 공개 시세 WebSocket: `wss://api.upbit.com/websocket/v1` (`ticker`, `trade`, `orderbook`, `candle`).
- 주문 생성: `POST /v1/orders` (인증·주문 권한 필요, 초당 최대 12회로 문서 안내. 실제 운영은 훨씬 낮은 내부 제한을 둔다).
- 주문 생성 테스트: `POST /v1/orders/test` (실제 주문 생성 없음; **모의 손익을 제공하는 페이퍼 브로커가 아님**).
- 주문 조회/취소: `GET/DELETE /v1/order`; UUID 또는 사용자 지정 identifier로 추적.
- 원화마켓 최소 주문: 5,000원. 현재 호가 단위를 사전 확인하고 주문 수량·가격을 정규화.
- API Key: IP 허용 목록 필요, 키당 최대 10개 IP 등록 가능. 최소 권한: 조회/주문. **출금 권한 절대 부여하지 않음**.
- JWT 서명 구현, 키 비밀 저장, 비밀값 출력·로그 기록 금지.
- API·WebSocket 요청 제한 정책은 변경될 수 있어 실배포 시 공식 문서 재검증 필요.

### 주문 안정성
1. `signal_id`와 `order_intent_id`를 DB에 고유하게 저장해 동일 봉 중복 주문 방지.
2. 주문 전 미체결 잔고·체결 내역을 확인.
3. 주문 요청 성공/실패/타임아웃 결과를 즉시 결정하지 않고 identifier·UUID 기준 실제 주문 상태 재조회.
4. 주문 결과 불명이면 **재주문하지 말고** 조회·알림·중단.
5. 부분 체결, 미체결 취소, 초과 수량, 재시도, 중복 응답, API 제한(429) 테스트.
6. 손절은 봇 의존 구현일 수 있으므로 서버/네트워크 장애 시 안전한 자동 청산이 보장되지 않음을 UI에 명시.
7. 내부 자산 대조(reconciliation)에서 불일치 발생 시 `SAFE_PAUSED` 모드로 전환.

## 7. 상태 머신과 모드 전환

- `BACKTEST`: 과거 시세로만 실행.
- `PAPER`: 기본 모드. 실시간 데이터, 가상 체결. 업비트 계정 키 불필요.
- `SHADOW`: 실거래 계정 읽기 권한만 사용하고 가상 주문과 실계좌 정보를 비교. 주문 전송 금지.
- `LIVE_ARMED`: 별도 배포 플래그, 관리자 재인증, 실제 주문 권한, 위험고지 및 사용자 승인 후에만 진입 가능한 향후 모드.
- `SAFE_PAUSED`: 신규 매수 불가. 기록·모니터링·알림 유지. 보유 포지션 처리 정책을 관리자가 확인.
- `EMERGENCY_STOP`: 신규 주문 차단. 미체결 취소/보유자산 매도는 **별도 명시적인 위험고지와 수동 실행**이며 성공 보장 불가.

**v1 출시 대상은 `BACKTEST/PAPER/SAFE_PAUSED/EMERGENCY_STOP` 중 실거래 없는 동작만. `LIVE_ARMED`는 개발 완료 정의에 포함하지 않는다.**

## 8. 대시보드 화면 정의

1. **홈 / 종합현황**: PAPER 표시, 봇 연결 상태, 가상 자산, 오늘/누적 실현·미실현 PnL, MDD, 오늘 매매 횟수.
2. **전략 연구실**: 3가지 전략, 연구 파라미터, 백테스트 기간, 워크포워드 결과, 승인된 버전.
3. **거래 내역**: 신호 생성 시각, 이유, 가격, 수량, 수수료, 체결·미체결, 익절·손절, 순손익.
4. **리스크 센터**: 1회/일일/전체 한도, 현재 위험 노출, 중지 원인, 연속 손실, 경보.
5. **운영 관리**: PAPER 시작/중지, 비상 정지, 알림 설정, 관리 계정, 배포 버전 및 감사 로그.
6. **리포트**: 날짜별 성과, 전략별 성과, 거래 비용, 최대낙폭, BTC 단순 보유 대비 비교.

모바일 우선: 상태와 비상 정지 버튼이 첫 화면에 항상 보이도록 하고, 수익률보다 **현재 모드와 리스크 상태**를 강조한다. 차트·수익률은 샘플 값과 실제 측정 값을 분리 표기한다.

## 9. AI 역할과 승인 체계

- **전략 연구원(AI)**: 시장 상태 분류, 전략 아이디어, 과적합 탐지, 백테스트 비교. 계정 키 접근 불가.
- **개발 담당(Claude Code)**: API 수집기, 백테스트, 전략 엔진, DB 및 테스트 구현. 병합 권한 제한.
- **품질검수(Codex)**: 리스크 엔진, 단위/통합/장애 테스트, 보안 검사, 코드리뷰. 프로덕션 키 접근 금지.
- **운영 관리자(사용자)**: 전략 승인, 운영 모드 선택, 중지/재개, 실거래 승인 결정.
- 모델이 새 전략을 제시하더라도 자동으로 배포하지 않는다. 주 1회 분석 리포트로만 제시한다.

- 전략별 MDD, 변동성, 거래건수, 순수익, Profit Factor, 시기별 손익, BTC 단순보유 성과 비교.

## 12. 필수 장애/보안 테스트

- WebSocket 60초 이상 데이터 단절 → 신규 매수 금지, 경고, 복구 후 데이터 갱신 확인.
- 오래된 캔들·결측 캔들·중복 캔들 → 주문 금지.
- API 429/5xx → 백오프, 재시도 제한, 동일 주문 재전송 금지.
- API 주문 요청 타임아웃 → 먼저 주문 조회, 상태 불명 시 중지.
- 복수 워커 동시 실행 → 잠금 또는 유일키로 주문 1회만 생성.
- 시스템 재부팅 → 이전 주문·포지션 복구, 대사 전 신규 매수 금지.
- 손절가 급격 이탈/갭 → 예상 손실보다 크게 체결될 수 있음을 시뮬레이션.
- 수수료 급증, 거래정지, 데이터 이상, 최소 주문액 위반 → 거래 거절.
- JWT 비밀키 로그 유출, 환경변수 출력, 관리자 로그인 우회, CSRF/CORS 및 종속성 보안 점검.
- 중지 버튼 → 신규 신호 및 주문 차단 확인. **자동 일괄 시장가 매도와 동의어가 아님**.

## 14. 개발자 작업 지시 (Claude Code / Codex 복사본)

> 프로젝트 `aegis-trade-ai`를 새로 생성한다. 기존 선물·MEXC 프로젝트의 API 키/주문 코드는 재사용하지 않는다. 현 버전은 업비트 KRW-BTC 현물의 PAPER 자동매매 시스템만 구현한다. 공식 업비트 API 문서를 최우선 참고하며, 불명확한 API 동작은 테스트로 확인한다. Python/FastAPI, 백테스트 모듈, PaperBroker, 별도의 Risk Gate, 모바일 웹 대시보드, 감사 로그, 자동 테스트를 순차 구현한다. API 키는 MVP에 필요 없으므로 절대 요청하거나 저장하지 않는다. 어떠한 주문 경로도 실계좌에 연결하지 않는다. 신호는 확정된 4시간봉만 사용한다. 거래당 최대 손실 0.5%, 주문당 자산 10%, 전체 BTC 노출 20%, 일손실 2%, 전략 최고점 대비 낙폭 8%, 연속 손실 3회를 기본 설정값으로 구현하고 테스트한다. 모든 모듈은 단위 테스트와 통합 테스트를 추가하고, 운영 기록이 누락되지 않도록 한다. 개발 PR은 데이터·전략·위험관리·PaperBroker·화면 순으로 쪼개어 작성하고, 실제 거래 기능을 추가하는 PR은 작성하지 않는다. 성능 결과를 생성하지 않았으면 수익률·승률 수치를 임의로 표시하지 않는다. 코드 구현 후 남은 제약과 미검증 항목을 보고한다.
